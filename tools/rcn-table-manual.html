1 · The idea in one minute

A table answers which one? A drawing answers what is this connected to? You almost always need them in that order, and the table exists so you are not asked to look at four hundred things at once.

So the motion is: scan a list, pick a row, and follow it into a small picture of what that row touches. Then grow the picture a hop at a time if you want more.

The table reads your records. It does not change them. Nothing you do here can alter the underlying data.

2 · Opening the table

Three ways in:

  • From a wiki page — find a table item and press Open Table ↗. This is the usual way. The table reads from that site's own records folder (§13); nothing else needs to be running.
  • Directly — open rcn-table.html. On a steward's laptop it shows what the live records hold; anywhere else give it a folder: ?src=https://…/assets/rcn-table/whatcom/.
  • From a spreadsheet — open rcn-table.html and press Open spreadsheet…, or drop CSV or Excel files onto it. Nothing else needs to exist. §15 says how to lay the sheet out and how to publish it.
  • Straight to a particular set of rows — add &kind=Entity (and db=whatcom when reading live records) to the address.

The two dropdowns at the top left choose which body of records and which kind of thing within it. The number beside each kind is how many rows it has.

4 · Finding a row

Filtering

Type in the Filter rows… box. It matches anywhere in any column you can currently see — so hiding a column also removes it from the search. The count changes to "24 of 189 rows" so you always know you are looking at a subset.

Sorting

Click a column heading to sort by it. Click again to reverse. A small triangle marks the sorted column. Numbers sort as numbers and text sorts alphabetically, without you having to say which is which.

Hovering a column heading tells you how full that column is — "category — 28% filled". Real records are patchy, and it is better to know it than to guess.

5 · Selecting, and comparing

Click any row to select it. The Inspector fills with everything known about that row.

Hold Cmd (or Ctrl) and click a second row, and the Inspector changes its job. It keeps the same attribute names but now shows you:

  • the value, where every selected row agrees;
  • […] 2 values, where they differ.

Attributes where everything agrees on being empty are left out entirely, because that tells you nothing. Two rows out of thirty-four columns will often collapse to four lines — which is the answer to "what do these have in common?"

Clear selection empties it. Clicking a row without Cmd starts a new selection.

6 · Columns

The Columns list at the bottom right has every column with a checkbox and how full it is. Untick to hide, tick to show.

Columns filled for fewer than one row in ten start hidden. They are not dropped — they are listed with their percentage so you can bring any of them back. A column that is empty for most rows may be exactly the one that matters for the row you care about.

Hidden columns are also excluded from filtering and from anything you export. If a search is not finding something you know is there, check whether its column is showing.

7 · Getting data out

ButtonWhat it does
CSVDownloads the rows you can currently see — after filtering, in the order you sorted, with only the visible columns. Opens in any spreadsheet.
→ Wiki itemSends the current view back to the wiki page that opened the table, where it becomes a table item other people can read and follow.

The wiki item carries up to 200 rows. If there are more, it says so — it records the true total so nobody mistakes the sample for the whole set.

8 · The table inside a wiki page

A wiki column is far too narrow for a real table, so the page shows the shape of one instead:

  • the title, and the dimensions in large type — 189×6;
  • the column names as small chips;
  • the first three row names, as links;
  • an Open Table ↗ button.

Hovering a column chip announces that column to the rest of the page. Any chart on the same page that understands columns will respond to it. Nothing has to be connected up for that to work.

9 · Names, links and ghost pages

The name in each row is an ordinary wiki link. Clicking it opens that subject's page beside the table.

Often that page will not exist yet, and you will get an invitation to write one. This is normal and it is useful. A link to a page nobody has written is a record that the thing was referred to — in the 2017 Whatcom records, 55 organisations, themes and people are named by some table without ever having a row of their own.

Because names are the link, a row in this table, a node in a drawing and a name typed in a paragraph all lead to the same page. They agree because they name the same thing, not because anyone connected them.

10 · Following a row into a picture

Select exactly one row and press Neighbourhood ↗. The Graph Tool opens with:

  • your row in the middle, drawn with a thick border;
  • everything it is directly connected to, ringed around it;
  • every line labelled with the relationship — funded by, part of, addresses;
  • colour by kind, explained in the legend.

The button is greyed out unless exactly one row is selected, because a neighbourhood is a picture of one thing.

This is why the table exists. Drawn all at once, the Whatcom records are 409 things and 770 links — a picture of nothing. Whatcom Community Foundation on its own is a clear picture of one foundation and the thirty-two organisations it funded.

11 · Expand and collapse

In that drawing, click any node and look at the panel on the right. If the substrate knows about it you will see Expand ↘.

Expanding brings that node's own connections in and attaches them to what is already on screen. The picture is not replaced — it grows. That is the difference between looking things up and following a thread.

If something arriving is already on the canvas, it is not drawn twice. The new line is drawn to the node already there. This is what lets two expansions meet in the middle and show you a shared funder or a shared theme.

Collapse appears once a node has actually added something, and removes exactly what that expansion brought in — including anything those nodes went on to add. It never removes what was on the canvas before you expanded.

Expand asks the records a fresh question each time, so it needs the substrate running. If it is not, you will get a message rather than a silent failure.

12 · Putting rows on a map

Select rows and press Map ↗, next to Neighbourhood. Anything in the current view that carries a location is drawn; what you had selected is picked out.

Unlike Neighbourhood, this does not need exactly one row — a map of many things is the normal case. The button is greyed out only when nothing in view has a location at all.

What gets drawn

The row is…Drawn as
a point — a person, a building, an NDCA filled circle. Selected rows are larger and amber.
an area — a watershed, a county, a school districtIts actual outline. Hovering brings one area forward when several overlap.
related to another thing on the mapA dashed line between them, labelled with the relationship.

Colour is by kind, and the legend across the top says which is which and how many of each.

Areas nest — a town inside a county inside a watershed — so fills are kept faint and the outline carries the shape. Bigger areas are drawn first so smaller ones stay visible on top of them.

Lines that go to an area

A line to an area ends at a small hollow dot inside it. That dot is the centre of the area's bounding box, not its true centre: for a crescent-shaped watershed it can fall outside the shape itself. It is honest as "this line arrives at this area" and wrong as "this is where the area is" — never measure anything from it. The exact boundary lives in the map data.

Clicking things

Click any point or area for its attributes and an Open its page ↗ link, which opens that subject in the wiki behind — the same page a table row or a graph node opens. Hovering shows the name, and for an area its size.

Coordinates come from the records, not from the map

The map asks the substrate for geometry, attributes and relationships. The table only tells it which rows are in view and which are selected. So a map can never show something the records do not say, and a link to a map works with nobody's table open.

Rows without a usable location are counted in the header, never quietly dropped — "22 of 41 rows mapped · 19 rows without coordinates". Latitude and longitude arrive as text from spreadsheets, so a blank, a stray word or a pair of zeroes all count as "no location" rather than being plotted somewhere in the Atlantic.

Where addresses became coordinates

Some rows were located from their street address rather than surveyed. Those carry lat_source, the query that was asked and what the service said it matched, so you can always see what produced a point. A geocode is a claim about an address: the address may be wrong, and a match may be a street rather than a door.

Of the 42 Whatcom organisations with an address, 39 were found and 3 were not. Those 3 have no coordinates rather than approximate ones. 38 of the 39 matched an actual building; one matched only its street.

Most of the addresses name a room rather than a building — Suite 204, #D-1, Ste 102 — which a service that resolves streets cannot match. Those are looked up without the suite, which finds the building the organisation is in, to within a few metres.

Every result is checked against the county it should be in before it is kept. That check matters: asking for 1610 West Grover Street, WA, 98264 returns a real West Grover Street — in Magnolia, Seattle, 145km from Lynden. It looked like a perfectly good coordinate and it was wrong. A result in the wrong county is discarded and the next form of the address is tried instead.

13 · Where the rows come from

The table reads named views of the shared records — it does not hold data of its own. The two dropdowns are choosing among those views.

What you pickWhat it asks for
The records dropdownWhich body of records — for example the 2017 Whatcom survey.
The kind dropdownWhich kind of thing within it — organisations, people, programmes, themes, NDCs, places.
Neighbourhood ↗One row's connections, as a drawing.
Map ↗The located rows, with their shapes and the links between them.

There is more than one body of records. whatcom holds the 2017 county survey — organisations, programmes, themes and people. rcngeo holds the network's own geography — the NDCs, a partner, and the places that contain them. The others hold the drawings.

Because these are named views rather than questions you have to compose, there is no query language to learn and no way to ask for something malformed.

Those views reach the table in one of two ways, and the table looks the same either way:

WhereWhat the table readsWho needs to do what
A wiki site (WikiCafe, or any site that is not on your own machine)A folder of files in that site's assets: /assets/rcn-table/<records>/. Plain JSON. Nothing runs; a reader needs no account and no software.The site's owner made the folder once (§15) and uploaded it. Only they can change it.
A steward's own laptop (a wiki on localhost)The live records — Neo4j, answered through the substrate on port 8768 — so the steward sees the database as it is, not as it was last exported.Neo4j Desktop and the substrate (python3 substrate/api.py) must be running.

A table item can also be pointed at another site's folder: double-click it and add a line src: https://their-site/assets/rcn-table/whatcom/. That is how one neighbourhood reads another's records without copying them.

14 · When something looks wrong

What you seeWhat it means
"Could not reach the export folder at …"The site has no /assets/rcn-table/<records>/ folder yet, or the item's src: line points somewhere that does not exist. The site's owner needs to make and upload the folder (§15).
"Could not load — is the substrate running?"On a steward's laptop: the live records are not reachable. Start Neo4j Desktop and substrate/api.py.
A mostly empty tableProbably the wrong kind selected. Check the count beside each kind in the dropdown.
Neighbourhood ↗ greyed outSelect exactly one row. Zero or several will not do.
A row name ending in (unspecified)Real data, not an error. In the 2017 records it means a grant went to the organisation without a particular programme being recorded.
The same organisation appearing as two kindsAlso real. Nineteen names in the Whatcom records are both an organisation and a programme, because the sheet used the organisation's name for its programme. It is reported rather than silently merged, because only a person can say whether that is right.
Expand adds nothingEverything that node connects to is already on the canvas. It will say so.
Map ↗ greyed outNothing in the current view has a location. Try another kind — in the 2017 survey no organisation was surveyed with coordinates, and only some have since been located from their address.
The map opens nearly emptyRead the header. It says how many rows were mapped and how many had no coordinates, which is usually the answer.
An area looks like it is in the wrong placeCheck whether you are looking at the area's outline or its anchor dot. The outline is right; the dot is a bounding-box centre and can sit outside a curved shape.
No lines on the mapLines are drawn only between two things that are both located. A relationship to something with no coordinates has nowhere to land.

15 · Making a folder for your site (stewards)

A site serves its table from a folder in its assets. There are two ways to make that folder. The first needs nothing installed.

From a spreadsheet, in the table itself

  1. Lay the records out as one sheet per kind of thing — Organization, Program, Person — with the name in the first column (or a column called Name) and one header row. A column called lat and one called long put a row on the map. Optionally add a sheet called Links with three columns, From, Relation, To, one row per connection; a name there that has no row of its own still becomes a node. An Excel workbook with several sheets, or several CSV files, both work.
  2. Open rcn-table.html and press Open spreadsheet… (or drop the files onto the table). The table, Neighbourhood and Map now work on what you opened, in memory. The footer says not yet published.
  3. Press Publish records ↓. The browser downloads a handful of small files — index.json, one table-….json per sheet, geo.json and graph.json — and asks once whether this page may download several.
  4. On your wiki, add an Assets item to a page and give it the text rcn-table/your-workbook-name. Drop the downloaded files on it. That text is the folder they land in; the slash makes it a folder inside rcn-table.
  5. Once per site, press Tool files ↓ for the three pages that do the work — rcn-table.html, rcn-table-map.html, graph-tool-v22.html — and drop them on an Assets item whose text is rcn-table. A site that already has them needs nothing here.
  6. A table item on any page of that site — with the line database: your-workbook-name in its text — now opens against your records.
  7. When the records change, open the new sheet, publish again and drop the new files on the same Assets item. They replace the old ones. The files are derived; nothing lives only in them.

The table does not merge two rows that name the same thing differently, guess a kind, or fill an empty cell. Those are decisions, and it leaves them to you.

From Neo4j, for a steward with a workbench

  1. Load your records into Neo4j with the loader for their shape — for example python3 substrate/load_whatcom.py reads the 2017 survey's CSVs. The loader rebuilds the database from the files every time, so the files stay the truth and the database can always be remade.
  2. Export: python3 substrate/export.py --bundle whatcom rcngeo (name the bodies of records you want to publish). This writes substrate/export/rcn-table/: the three tool files beside one folder per body of records.
  3. Put them on the site the same way: the tool files on an Assets item named rcn-table, each records folder's files on one named rcn-table/whatcom, rcn-table/rcngeo, and so on. Re-run and re-drop when the records change.

Several bodies of records in one folder

Where everything has to sit in one folder — the RCN Map’s NDC Assets, for instance — give each export a name in front: python3 substrate/export.py whatcomcoops --prefix whatcom-coops-export writes whatcom-coops-export-index.json, whatcom-coops-export-table-coop.json and so on, and the table is pointed at …/whatcom-coops-export- (a source ending in a dash is a name in front, not a folder). Pick a name nothing else in the folder starts with.

The whole Whatcom survey is about half a megabyte. Copy the folder to a phone and the table still works.

16 · Moving between tools (⇄)

Open from a set link, every one of the four RCN views — the Graph Tool, the RCN Map, the Timeline and the Table — shows a small bar at the bottom of the window:

⇄ Co-ops of Whatcom County · 🕸 Graph · 🗺 Map · ⏳ Timeline · ▦ Table

Press one and the same dataset opens in that view, on whatever you have selected now. Pick a co-op in the graph, press ⏳ Timeline, and the timeline opens on that co-op’s history; press ▦ Table and its row is selected. Each view keeps one tab, so going back and forth reuses tabs instead of piling them up. The bar is hidden in Present mode.

A set link looks like rcn-table.html?set=whatcom-coops.set.json&sel=cfc: the set file says where the dataset lives in each view, and sel is the thing to open on. The id is the one the map uses for its points; the graph, timeline and table carry the same id, which is what lets the selection travel. Without ?set= there is no bar and the tool behaves exactly as before.

In the Table, the selection that travels is the one selected row; its id comes from the column the set names (idColumn — mapId for the co-ops). Arriving with sel, the table selects that row and scrolls to it. The set also names where the table’s files are (table.src) and which kind to open.
