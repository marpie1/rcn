1 · Core ideas in one minute

The tool holds one issue at a time. An issue is a question with a footprint, and it has five parts:

PartWhat it is
Issue polygonThe gold dashed boundary that defines the scope. Everything inside it is in the argument.
ParcelsIndividual properties inside the boundary, each with a stance and a set of facts (lot size, zoning, HOA, and so on).
BoundariesThe governments whose rules overlap the issue — typically a municipality and a county.
LawsThe specific rules in play, each tagged with the jurisdiction it comes from and what it does.
ActionsWhat has to happen next, and whether it is pending, contingent, or not started.

Everything except stance is public record. That is what makes this an instrument you can build before you have spoken to anybody.

2 · Opening an issue

Open issue-polygon-map.html in a browser. With no issue specified you get the landing page, which offers three ways in:

  • ↑ Open file — choose a .json issue file or a .geojson export from disk.
  • ↑ Load pasted — paste the contents of either directly.
  • Search — find a place by name to start from a location.

By URL

Add ?issue=<key> and the tool fetches issue-data/<key>.json alongside itself:

issue-polygon-map.html?issue=superior-az--chickens

The path is relative, so this works served by sofi-proxy, by any static host, or from a file:// copy — as long as issue-data/ sits next to the HTML. Add ?data=<base> to point at a different folder, e.g. a published issue directory.

If the fetch fails you land back on the landing page with the reason shown, and can still open the file by hand. A failed ?issue= is usually a missing .json in issue-data/ or a typo in the key.

3 · The interface

Map on the left, sidebar on the right.

The sidebar carries, top to bottom: the issue title and community; the layer toggles; the stance tally; the laws in play, colour-coded by jurisdiction; the action list; and the export controls.

The toolbar above the map holds the editing and sharing actions: + Add Parcel, ✎ Draw Polygon, ↩ Undo, ↓ Export GeoJSON, ↑ Load GeoJSON, ↧ SVG, ↧ PNG, 🖨 Print, and ↗ Copy view link.

4 · Layers & basemaps

Each layer toggle turns a layer on or off and refits the view to whatever is still visible. Available layers depend on what the issue file provides:

LayerShows
MunicipalityTown or city boundary, with a popup carrying its code status and any note about preemption.
CountyCounty boundary, with the county-level standard in its popup.
Issue polygonThe gold dashed scope boundary.
ParcelsAll parcel pins.
NDCA pink ring around the anchor parcel — the Neighborhood Development Cooperative convening the issue.

Basemaps: Light, OpenStreetMap, Topo, Satellite, Dark. Satellite is the useful one for arguments about lot size, setbacks and what is actually built on a property.

5 · Parcels

Adding one

  1. Click + Add Parcel.
  2. Click the location on the map.
  3. A pin appears with a generated id. Open its popup to fill in the details.

Parcel fields

FieldMeaning
idParcel number. Use the real APN where you have it — generated ids are placeholders.
labelStreet address or a name people will recognise.
stancePro Con Unknown — see §6.
lot_sizeAcres. Often decides whether a setback rule can even be met.
zoningFree text, e.g. R-1.
hoaWhether an HOA covenant applies — frequently stricter than any government rule.
qualifies_hb2325Issue-specific eligibility flag. Rename per issue.
desired_flockIssue-specific quantity. Rename per issue.
notesFree text. Put your source here — especially for stance.
ndcMarks this parcel as the NDC anchor.

Delete a parcel from its popup with ✕ Delete parcel. It is undoable (§9).

6 · Stance & the tally

Stance has exactly three values — pro, con, unknown — set from buttons in the parcel popup. The pin recolours immediately and the tally updates.

Unknown is the correct answer until somebody asks. Public record tells you who owns a parcel and how big it is. It does not tell you what they think. Inferring a stance from a yard sign, a voter file, or a neighbour's opinion puts words in someone's mouth on a map you intend to show a council. Leave it Unknown and record in notes what you actually know.

The tally is the honest measure of coverage: a large Unknown count is not a failure, it is the work remaining, and it is the number to bring to a meeting when someone claims the neighbourhood is against something.

7 · The issue polygon

Drawn from the issue file as a gold dashed boundary. Its popup shows the issue title, its id, the parcel count, and the scale ladder from neighbourhood up to state. Two controls sit in the popup: ↗ Copy link (§11) and ✕ Delete polygon.

Deleting is undoable, and reimporting a GeoJSON that contains the polygon restores it (§12).

8 · Drawing & reshaping a polygon

Draw

  1. Click ✎ Draw Polygon.
  2. Click each corner in turn. Existing polygons pass clicks through, so you can trace over them.
  3. Finish. The shape appears with a default name.
  4. Use ✎ Rename in its popup to give it a name that says what it is.

Reshape

A drawn polygon can be edited after the fact rather than redrawn. Turn on shape editing and each vertex gets a draggable handle:

  • Drag a handle to move that corner.
  • Insert a vertex to add detail along an edge.
  • Remove a vertex to simplify.

Each change is undoable. Drawing and shape editing both want your clicks, so turning on one turns off the other.

Use a drawn polygon for anything that isn't the issue boundary itself — a proposed overlay district, the area within 100 ft of a school, the blocks canvassed so far. Unlike the issue polygon, drawn polygons carry a name of your choosing.

9 · Undo

↩ Undo steps back through parcel edits, stance changes, deletions, polygon drawing and vertex edits. Reach for it before redoing work by hand.

10 · Search

Search by place name (via OpenStreetMap's Nominatim service) to jump the map somewhere. Useful when starting a new issue from nothing, or checking where a boundary actually runs. Requires an internet connection.

11 · Deep links

Three kinds of shareable URL, all built for you by a Copy link control:

LinkBuilt byOpens
?issue=<key>&parcel=<id>Copy link in a parcel popupThe map zoomed to that parcel with its popup open
?issue=<key>Copy link in the issue polygon popupThe issue at its default view
?issue=<key>&lat=&lng=&zoom=↗ Copy view linkExactly the view you are looking at

Send a parcel link when the conversation is about one property. Send a view link when it is about an area. These are the difference between "look at the map and find the corner of Main and Belmont" and a link that just opens there.

12 · Import & export

Export

↓ Export GeoJSON writes a standard FeatureCollection containing the issue polygon, every parcel as a point, and any drawn polygon. It opens in QGIS or anything else that reads GeoJSON.

Import

↑ Load GeoJSON takes that file back, from disk or pasted. Features are recognised by properties.type:

properties.typeGeometryRestores
ParcelPointPin, stance and all fields
IssuePolygonPolygonThe issue boundary, its title and id
CustomIssuePolygonPolygonA drawn polygon and its name

Importing replaces the current parcels rather than merging. The status line reports what came back, e.g. Loaded 12 parcels + issue polygon. When an issue polygon is restored the view refits to it, so importing an issue from another area doesn't leave you staring at the wrong place.

Fixed August 2026. The exporter always wrote the issue polygon, but the importer used to ignore it — so the boundary that defines the issue silently died on its own round-trip. Parcels came back, which made it look like the import had worked. If you have GeoJSON exports made before this fix, they are fine: the polygon was always in the file, only the reading of it was missing.
Hand-editing GeoJSON: coordinates are [longitude, latitude] — the opposite order from what most people write. Getting it backwards produces no error, just a parcel in the wrong hemisphere. Full field reference and traps: tools/schemas/issue-polygon-map.md.

13 · Pictures — SVG, PNG, Print

ControlGives youBasemap?
↧ SVGThe current view's shapes — parcels, boundaries, polygons — as editable vectorNo
↧ PNGThe same shapes as a raster imageNo
🖨 PrintThe full map through your browser; choose "Save as PDF" for a fileYes
SVG and PNG do not include the basemap tiles. You get the shapes on a blank background — ideal for overlaying on something else or editing in Illustrator, and confusing if you expected streets. When the picture needs to show where — a council packet, a door-knock sheet — use Print instead, which renders the basemap with everything else.

14 · Authoring an issue file

An issue is a single JSON file in issue-data/, named <key>.json. Top-level shape:

{
  "meta":       { "id", "title", "community", "ndc", "coordinator",
                  "date", "status", "description", "apn_prefix" },
  "issue":      { "centroid": [lat, lng], "polygon": [[lat, lng], ...] },
  "parcels":    [ { "id", "label", "latLng", "stance", ... } ],
  "boundaries": { "municipality": {...}, "county": {...} },
  "laws":       [ { "name", "jurisdiction", "effect", "tag" } ],
  "actions":    [ { "step", "type", "status", "description" } ]
}
Coordinate order differs between the two formats. The issue .json uses [lat, lng] throughout, because that is what the map library takes. Exported .geojson uses [lng, lat], because that is the GeoJSON standard. Both are correct; they are different files. Do not copy coordinates from one into the other without swapping.

laws[].jurisdiction should be state, county or municipality — it drives the colour coding. actions[].status is pending, contingent or not_started.

15 · Working patterns

Starting an issue from public record

  1. Draw the issue polygon around the area actually affected — resist making it bigger than the argument.
  2. Add the parcels inside it from assessor records. Leave every stance Unknown.
  3. Add the jurisdictions that overlap, with the actual code citation in each popup.
  4. List the laws, tagged by jurisdiction, including the ones you suspect but haven't verified.
  5. Turn each unverified thing into an action with a name attached.

That map is buildable in an afternoon, needs nobody's permission, and is a far better opening than an opinion.

Canvassing

Work the Unknown pins. After each conversation set the stance and put the source and date in notes. The tally becomes an honest report of coverage, and the parcel deep links let two people split an area without stepping on each other.

Taking it to a hearing

Print the map with the tally visible. The argument it makes is specific: here is the boundary, here is the rule, here is who is inside it, and here is how many we have actually asked. Bring the unknowns rather than hiding them — the credibility is in the gaps.

Pairing with the other tools

The map says where. When the question turns to why the situation persists, that is the Graph Tool; when it turns to what happened when, that is the Timeline. A parcel id can carry across as a node or interval id, so the three stay linked.
