RCN Graph Diagramming Tool

Introduction — what it is, what it does, and why it exists

Tool version: v22  ·  Document updated: August 17 2026
Introduction User Manual Open the Tool ↗
The RCN Graph Tool is a single HTML file — no install, no account, no server — that treats a graph diagram as simultaneously a Neo4j data model, a Causal Loop Diagram, and a systems analysis workspace. The three framings are not separate modes: they are the same graph, analyzed from different angles depending on what you need to know.

Who it is for

The tool was built for the RCN's neighborhood development work, where a single diagram often needs to function as a knowledge graph (queryable in Neo4j), a causal map (readable by a systems thinker), and a whiteboard artifact (shareable as a URL or image). Most diagramming tools optimize for one of these uses. This tool holds all three at once.

It is useful to anyone who draws graphs to think — whether that means mapping causal feedback in a community system, designing a Neo4j data model, sketching an Ecology–Institutions–Politics analysis, or producing a publishable diagram of a complex system.

What it does

Graph drawing

7 node shapes, 80-color palette, custom borders, per-node font control, in-place editing, resize handles, curved bezier edges, self-loops, dotted/dashed styles.

CLD analysis

Polarity (+/−) and delay marks on edges — available in every mode, not only CLD. Automatic reinforcing/balancing loop detection with labeled overlay. A one-click check flags every edge whose polarity is still unset, since those count as neutral and can quietly grey out a real loop. Animated polarity propagation — step through causal chains visually. Driver tree views show upstream and downstream structure for any variable.

Driver trees

Select any single node and the Driver Trees section appears in the right panel — click Effects ▶, ◀ Causes, or ◀ Both ▶ to open a full-screen radial layout showing what flows from or toward that variable. Unique to this tool.

EIP mode

Column overlay for Ecology, Institutions, and Politics — the three domains of the EIP framework. Node placement on the canvas becomes positionally meaningful.

NRM mode

Neighborhood Risk Management — a Tripod Beta causal analysis overlay. Pre-typed, color-coded nodes for Underlying Causes, Preconditions, Immediate Causes, Incident Trios (Agent / Object / Event), and Barriers. Click a type in the palette, then click the canvas to place it.

Neo4j integration

Import CREATE and MATCH Cypher statements. Export Cypher with full multi-label support. Designed to replace Arrows Tool for teams that also need CLD analysis.

Vensim interop

Import and export .mdl (Vensim MDL) and XMILE files — including polarity preservation. Applies to Causal Loop Diagrams only; stock-and-flow and full system dynamics models are not supported.

Graphviz .dot

Import and export .dot files with full round-trip fidelity: colors, labels, edge weights, node shapes, and graph-level attributes (rankdir, splines) all survive the trip. Layout uses Dagre, not the Graphviz engine.

Annotation layer

Notes and key/value properties on every node and edge. URL-valued properties become clickable links in hover tooltips. Properties export to Cypher as node/edge attributes.

Trace mode

Mark edges as members of up to four named pathways (T1–T4). Animate each pathway in sequence to walk through a causal chain, process flow, or argument structure. Edges can belong to multiple traces simultaneously, and any one trace can be cleared from the whole graph in a single click without disturbing the others.

Route counting

Select any two nodes and get the number of distinct routes running from the first to the second, broken down by how many steps each takes — plus the count coming back the other way, which is usually very different. A wide gap says the relationship is strongly one-directional; a zero says there is no causal path at all in that direction.

Wardley mode

Renders the graph on a Wardley Map grid — evolution axis (Genesis → Custom → Product → Commodity) across the bottom, value chain (Invisible → Visible) on the left. Positions carry meaning, so auto-layout is disabled here; a node's evolution and visibility are the source of truth and the tool writes your dragging back into them.

Wardley maps written by Claude Chat

Paste wardley-chat-card.md into a Claude Chat conversation, say what you want mapped, save the JSON it hands back, drag it in. A node needs four fields — label, id, evolution, visibility — so there is little for a language model to get wrong, and a validator catches the rest before you open anything. Correcting Chat's positions by dragging is the actual analysis.

Rent Band Analysis

Adds a second claim to a Wardley map: not only where a component is, but where it lands once someone stops paying to hold it back. A dashed shadow node marks the forecast position, a translucent band spans the gap carrying the rent figure, a pin names the causal loop holding it, and a pressure arrow lists on hover the forces pushing and the mechanisms — with annual costs — holding back. Hover text survives into SVG export, so a printed map still answers "says who, and when".

Legend

Persistent legend section in the sidebar. Auto-derives entries from node colors — including known Wardley palette mappings. Editable labels, color pickers, show/hide canvas overlay. The on-canvas legend carries its own collapse chevron, so it can be folded to a single title bar when it covers the diagram. Saves with the diagram JSON.

OPM mode

Object Process Methodology (ISO 19450). Ten structural and procedural link types — including Classification-Instantiation — with an auto-suggesting relationship picker. OPL sentences generated automatically from every typed edge. Export as plain-text OPL, Neo4j Cypher, or CSV triples.

LOP mode — Linkage of Processes

Deming's organization-as-a-system diagram, in the vocabulary of The Improvement Guide and Quality as an Organizational Strategy (Langley, Moen, Nolan, Nolan, Norman, Provost; Norman, Provost, Moen). Four labelled bands — aim and leadership, the value-added chain, support processes, information — with suppliers on the left and customers on the right.

Twelve node types and seven typed linkages, and the linkage type is read from what you connected rather than chosen from a menu: a supplier into a process supplies, a measure into design informs. Key processes number themselves in flow order, and each carries an owner and a measure that appear in a live List of Processes beside the map — the numbered table both books pair with the picture.

Check linkage reads the map back against what the books ask of it: a process with no owner or no measure, a customer with no stated need, and above all a map where no information returns anywhere — a pipeline rather than a system. Export the picture as SVG or PNG, the list as CSV or markdown, the whole thing as Neo4j Cypher.

VSM mode — Value Stream Mapping

Cindy Jimmerson's healthcare value stream map (Value Stream Mapping for Healthcare Made Easy), not the Rother/Shook manufacturing one. One patient, one condition, one observation, times recorded at the gemba. Five lanes: the four flows that must converge at the point of care — patient, provider, information, supplies — plus the timeline.

Nine node types and seven flows typed by what moves, read from what you connected rather than chosen from a menu. Storm bursts mark every problem seen; each is a candidate A3, and exactly one can be marked as the one worth writing.

The sawtooth is computed, not drawn — the tool sorts the timed steps over the moving flows, puts value-added time on the upper ledges and waiting below, and prints lead time, value-added time and the ratio between them. That ratio is usually the moment a room goes quiet. Check observation tests an observation rather than a diagram: no times recorded, nothing in the patient lane, or a stream that is all value-added and no waiting — which almost never survives real watching.

VSM→A3 hands a storm burst straight to the A3 tool, pre-seeded with the burst list and the observed times. Map the stream, find the bursts, A3 the worst one.

Layers

Assign any layer name to nodes or edges (e.g. Financial, Physical, Information). A Layers panel appears in the sidebar with toggle buttons — hiding a layer hides its nodes and all connected edges at once.

Free annotation lines

+ Line and + Arrow draw lines that are not connected to nodes — for grouping boxes, call-out arrows, dividers, and other annotations. Configurable color, width, dash style, arrowhead (none / → / ← / ↔), and label. Saved in JSON and exported in SVG/PNG.

Triples

Promote any edge to a reifiable triple (T01, T02…). A dot appears at the edge midpoint carrying an ID, label, status (healthy / degraded / broken), strength, and notes. Draw meta-edges from any node to a triple dot to model relationships-about-relationships — agreements, interventions, or trust levels attached to a specific causal link.

Sequential-add hotkeys

Press e to enter sticky Edge mode — the tool stays in Edge mode after each edge is drawn, ready for the next. Press n for sticky Node mode. Escape exits back to Select. Clicking the toolbar buttons keeps the original one-shot behavior.

Presentation view

Press P or click ⛶ Present and every control disappears — toolbar, sidebar, search box, mode banners, hint strip — leaving the whole fullscreen window to the graph, refitted to the new space. What stays is what belongs to the picture: the legend, the EIP columns, CLD loop labels, hover tooltips, and the propagation and trace animation controls, so a loop can be walked through live in front of a room. Nothing is read-only; the controls are hidden, not disabled. Escape returns you to exactly the pan and zoom you left.

Share, print & archive

Export as SVG, PNG (2×), JSON, URL, or Snapshot. SVG exports embed node and edge notes and properties as <title> elements — browsers show them on hover with no JavaScript required. Snapshot produces a single self-contained HTML file with the diagram baked in — open it in any browser, no JSON file needed, no server required. The URL encodes the full graph state for quick sharing. Print the current viewport directly from the tool.

How it differs from the alternatives

Six tools are most likely to be reached for when doing the same work. Here is the honest comparison — not just what this tool does, but what each alternative does well and where it falls short.

PowerPoint / Keynote / Google Slides Different category

Slides tools are where most diagram-drawing actually happens, which is the problem. A PowerPoint arrow is a decoration — it has no source node, no target node, no polarity, no properties, and no identity. It cannot be queried, exported to a database, or analyzed for feedback loops. Moving a node means manually re-routing every connected arrow. The diagram looks like a graph but behaves like a painting.

The RCN tool treats every element as structured data from the moment it is drawn. Edges know their source and target; nodes carry properties; the graph can be exported to Neo4j without any re-entry. Slides remain useful for presenting a finished diagram — not for building one that needs to be reasoned about.

draw.io / Diagrams.net Good diagramming, no systems analysis

draw.io is excellent general-purpose diagramming software — rich shape libraries, good layout tools, widely used. But it has no concept of polarity, no feedback loop detection, no Cypher export, no XMILE interoperability, and no driver tree analysis. A CLD drawn in draw.io is semantically inert: it looks correct but cannot be analyzed. It is the right tool for org charts, flowcharts, and architecture diagrams. It is not built for systems thinking.

yED Graph Editor Powerful layout, no CLD or Cypher

yED has excellent automatic layout algorithms and handles large graphs well. It requires a desktop installation and its native format does not interoperate with Neo4j or Vensim. Like draw.io, yED has no notion of causal polarity, feedback loops, or systems analysis modes. Its strength is visual organization of large structural graphs; its weakness is anything that requires the diagram to carry semantic meaning.

Loopy CLD-first, but limited scope

Loopy is the closest in spirit: a browser-based causal loop diagram tool, free, and surprisingly elegant. It pioneered the idea of interactively nudging a variable and watching the effects propagate through the loop — which inspired this tool's animated propagation feature. But Loopy uses fixed circle nodes, has no Cypher export, no Vensim interop, no delay marks, no driver trees, no multi-select, no property annotation, and limited export options. It is ideal for teaching the concept of feedback loops. It is not designed for building diagrams that also need to function as data models or analysis artifacts.

Neo4j Arrows Tool Direct predecessor — Cypher only

Arrows is the direct predecessor for Neo4j data modeling work and the source of the Arrows JSON import format. It does the Cypher round-trip well. But Arrows is cloud-only, has no CLD mode, no polarity, no loop detection, no XMILE, no driver trees, and no EIP overlay. Teams that started with Arrows to design Neo4j data models and then needed to analyze causal structure were the original motivation for building this tool. The RCN tool is a full replacement for that workflow, and extends it into territory Arrows was never designed to reach.

Vensim Professional SDM — different audience

Vensim is the dominant professional environment for Causal Loop Diagrams and System Dynamics Models. It is authoritative for that work and not a competitor in any simple sense. The key differences: Vensim is commercial ($600–$2,000+), requires a desktop installation, has no Cypher export, and is designed for professional simulation modelers rather than collaborative knowledge-mapping. (Vensim PLE is free for academic and personal use.) The RCN tool does not attempt to replace Vensim's simulation capabilities, and the interoperability is limited to Causal Loop Diagrams — stock-and-flow structures and full system dynamics models are out of scope. What it does offer is a lower floor for CLD sketching and analysis, with MDL and XMILE import/export — including polarity preservation — as the bridge into Vensim when simulation is the right next step.

What exists only here

  • Unique
    Multi-domain integration. No other tool in this field combines native Neo4j Cypher round-trip, full CLD analysis (polarity, delay, loop detection, animated propagation, driver tree layout), Vensim XMILE interoperability, and Tripod Beta risk analysis (NRM mode) in a single free tool. Arrows does Cypher but not CLD. Loopy does CLD but not Cypher. Vensim does CLD/XMILE but is commercial and has no Cypher. No tool surveyed combines any of these with Tripod Beta causal analysis.
  • Original
    Driver tree analysis. Select any node — Driver Trees buttons (Effects ▶, ◀ Causes, ◀ Both ▶) appear immediately in the right panel. Open an Effects Tree (what does this variable affect?), a Causes Tree (what drives this variable?), or a Center (Both) view showing the full upstream/downstream structure to any depth. Repeated nodes are flagged and clickable to highlight back in the main diagram. This view does not exist in any other tool surveyed.
  • Unique
    Animated polarity propagation. Long-press any node in CLD mode, choose ↑ or ↓, and watch the causal effect ripple through the graph — one hop at a time, color-coded by polarity, with configurable speed and a serialized step mode. Loopy has a simpler version of this; no other comparator does.
  • Unique
    Single HTML file deployment — including shareable snapshots. The entire tool is one file. No server, no install, no account. Open it from a USB drive, email it, drop it in a shared folder, run it in an air-gapped environment. The only comparator that matches this is Loopy. Everything else requires a server, a cloud account, or a desktop install. The Snapshot export extends this further: it produces a copy of the tool with the current diagram embedded — one HTML file that anyone can open to see and interact with the diagram, no companion JSON needed.
  • Unique
    Graphviz .dot round-trip. Import and export .dot files with full fidelity — colors, node shapes, edge weights, graph-level attributes, multi-line labels. Enables integration with the wide ecosystem of tools that read and write Graphviz format. Note: layout is handled by Dagre, not the Graphviz rendering engine — placement is directionally correct but less precise than native Graphviz output.
  • Original
    Reifiable triples. Any edge can be promoted to a first-class triple — it receives an auto-incrementing ID (T01, T02…), a visual dot at its midpoint, and a panel for status (healthy / degraded / broken), strength (0–1), and notes. Other nodes can then be connected to the triple dot via meta-edges, enabling RDF-style relationships-about-relationships: annotate that a specific causal link is contested, governed by an agreement, blocked by a barrier, or acted on by an intervention — all without restructuring the underlying graph.
  • Original
    The legend is the registry. In most diagramming tools the legend is a picture of the color scheme — a second thing you keep in sync with the drawing by hand, and the first thing to go stale. Here a legend row defines a kind of thing, and nodes and edges follow a row rather than carrying their own styling. Restyle the row and every element following it changes at once; override a single element and it diverges on that one property while still following the row for everything else. A diagram a group can read has six to eight kinds in it, and the panel says so — it warns above eight rows and reports how many elements are following no row at all. The legend stops being decoration and becomes the vocabulary the drawing is written in.
  • Original
    Exports that describe themselves. Styling by registry creates a trap: an element that follows a row needs no color of its own, so the saved file can be perfectly correct on screen and yet look entirely unstyled to anything that is not this tool — a database projection, a converter, an AI assistant reading the file, or a person scanning the JSON. On export the tool resolves each element's real appearance and writes it down alongside the row it follows, so the file says what you saw. The row still wins on reload, so the legend remains the single place to restyle.

Honest gaps

GapNotes
Real-time collaboration The single-file architecture makes live multi-user editing non-trivial. FedWiki integration is the natural path for collaborative workflows.
Large graph performance Force layout above 200 nodes is slow. The synchronous tick path helps but does not fully solve it.
Mobile / touch Designed for desktop. Long-press works on touch devices but the right sidebar is tight on small screens.
Persistent storage No server means no auto-save. JSON export is the save format. URL and Snapshot export both preserve full state — Snapshot as a self-contained HTML file, URL as an encoded link.
Property type hints All properties currently export as strings. Type annotation (integer, boolean, float) is planned for a future version.

Positioning statement

The RCN Graph Tool occupies a unique position: it is the only free, open source, single-file browser tool that treats a graph diagram as simultaneously a Neo4j data model, a Causal Loop Diagram, a Tripod Beta risk analysis, an ISO 19450 OPM process model, a Deming linkage-of-processes map, a Wardley Map, a pathway trace, and an RDF-style reifiable triple graph — all without leaving the browser. These are not separate modes with separate data: they are the same graph, examined from different angles depending on what you need to know.

The OPM mode is particularly significant for neighborhood work: it generates Object Process Language (OPL) sentences automatically from every typed relationship in the diagram. A drawing that says "Bantam Restaurant is an instance of On Street Business" is not just a picture — it is a precise, exportable claim readable by anyone. Dov Dori designed OPM for complex engineered systems; this tool brings that discipline into community systems thinking with no installation and no prior OPM training required.

This reflects the RCN's foundational commitment: that viable neighborhood-scale governance requires tools that are as rigorous as enterprise software and as accessible as a shared document.
