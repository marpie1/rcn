1 · Opening it and loading files

tools/graph-composer.html opens in a browser with no install. Family colours, the taxonomy and the set list all arrive as <script> sidecars, so they work whether the file is opened from disk or served.

One thing does need a server: loading a set. The set button has to read the subgraph files, and fetch() cannot read a file:// URL — Chrome throws TypeError: Failed to fetch. Opened from disk, the buttons are replaced by a note saying so; drag the files in instead, or serve the folder over http. Everything else, colours included, behaves identically either way.

Getting subgraphs in

  • Set buttons under the search box load a whole curated set in one click — EIP aspects — variabilized (16) and EIP aspects — original (16). This is the usual way in.
  • Drag and drop one or many files anywhere on the window.
  • + Load at the top of the beam opens a file picker.
  • Demo graphs (zoning-rules, land-trust, public-hearing) load automatically so the tool is never empty on first open.

A set button loads past the browser cache, replaces any earlier copy of the same set rather than stacking a second one, and ticks only that set — so the composite is the set, not the set plus whatever else was lying around. The sets themselves are listed in tools/graph-sets.js; that file is the one place to register a new subgraph, because HTTP cannot list a directory.

A set knows nothing about any particular schema — it is a name, a directory and a list of filenames. Adding your own is three lines of JSON.

What it accepts

FormatNotes
RCN graph JSONThe house format — what the Graph Tool saves. nodes + edges.
Ward's Graph JSONnodes + rels.
Arrows-ishEdges may use src/tgt, from/to, or source/target.
JSONLIf a file won't parse as JSON, the first line is tried.

Shape, colour, border, width, curve, polarity and delay all survive composition, so an exported composite still looks like what you drew.

2 · The beam

The left column is the beam — every loaded subgraph, grouped by where it came from (demo, loaded, partitions, or whatever label it was added with). Each row shows:

  • a checkbox — tick to include it in the composite
  • its name
  • a badge when it overlaps your selection (see below)
  • its size as 6n/7e — six nodes, seven edges
  • a × to remove it

Search at the top filters by node content — it matches against node types and instance names, not file names, so you can find which subgraphs mention a particular thing.

3 · Reading the colours

The beam uses two independent channels, so a row can carry both at once without ambiguity.

What you seeWhat it means
●Shares nodes with one subgraph you have ticked
●●… with two
●●●… with three or more
blue textMatches what you typed in the search box

Background and stripe mean overlap. Text colour means search. They never mean the same thing, so blue text on a tan stripe reads cleanly as "matches my search and shares nodes with my selection."

Hover the badge and it names the shared nodes: "shares 4 nodes with 2 selected subgraphs: Culture, Ideal, Org, Value."

The highlight uses the same key as the merge, so it is a promise, not a hint. If a row lights up, compositing it really will fuse those nodes rather than add them alongside.

4 · Composite, Bridge, Partition

Composite

Merges everything ticked. Two nodes from different subgraphs become one when their identity matches at the current Detail level; their properties are merged. Duplicate relations of the same type between the same pair collapse to one.

Bridge

A stricter question than the highlight. Bridge marks subgraphs that touch two or more of your selection — the ones that would connect pieces you already have, closing a loop between them. Use the highlight to see all overlap; use Bridge when you're specifically hunting for the piece that joins two islands.

Partition

Splits the current composite into its disconnected parts and adds each back to the beam as a new subgraph. Useful for pulling a tangle apart, or for checking whether what you composed is actually one connected system.

A fully connected graph partitions into one piece — that is not a failure, it's the answer. The EIP schema does exactly this: 25 nodes, all connected, so Partition returns it unchanged. Subgraphs there have to be curated, not derived.

5 · Detail — the four levels

Every node already carries four nested answers to "what is this?". The Detail control picks which one counts, and it is not a relabelling — the level is the identity function, so switching it re-composites. A coarser level is a genuine contraction of a finer one: each of its nodes is an equivalence class of the level below.

LevelIdentityExampleAll 16 EIP aspects
familylookup in families.jsDoing8 nodes
schemaschemaLabelAction24 nodes
variable+ labelEffectiveness of ACTION25 nodes
instance+ props.nameFix the Elm St culvert25 nodes

The goal is few schema labels carrying many variables, so the contraction should get more dramatic over time. The Node types panel reads that ratio off directly: it tallies by schema label at every level, so at variable level a count above 1 means that concept has been elaborated. Today only Affect has — Affect 2, Positive and Negative.

Instance level looks identical to variable level in the EIP set because every props.name is still "?". That is the level sitting empty, waiting for real data — it separates the moment you put named instances in.

Why polarity disappears at the top two levels

A signed link needs a quantity at both ends. A bare concept has no magnitude; only a variable of it does — "Action" cannot increase, but "Effectiveness of ACTION" can. So at family and schema level polarity is undefined by design rather than missing, and is dropped rather than reconciled. Where two variables of one concept push a third in opposite directions, that disagreement is real information belonging to the variable view; averaging it into a "±" on the skeleton would say nothing.

Those two levels also fold parallel edges into a single arrow, keeping the verb when the folded edges agree and listing what went in via the tooltip.

group by family

The checkbox under Detail draws each family in its own labelled box. It is off by default. Faceting is the second encoding channel the palette needs — a box names its family in words and separates confusable fills in space — but it forces the graph wider and flatter, so it reads better as a printed or projected reference than as the working view.

6 · The numbers

StatMeaning
nodesNodes in the composite, after merging
edgesRelations in the composite
mergedHow many nodes were recognised as repeats and fused
1-sourceHow many nodes rest on a single drawing. These are where the model is thinnest — one witness, nothing corroborating it. Goes amber past half. All 16 EIP aspects at schema level: 10/24.
sourcesHow many subgraphs went in
typedHow many source nodes carry a schemaLabel. Goes amber when short of the total.

typed is the one to watch. A node without a schema label falls back to its display label for identity, which means renaming it for legibility will silently stop it merging with its siblings. 75/75 means nothing is relying on its display text.

7 · The drawing

The composite renders through Graphviz. Every visual channel carries exactly one meaning, and no meaning rides on two channels at once.

ChannelCarries
node fillIts family, as a pale tint. Pale because node text is always black — worst contrast on the canvas is 12.7:1.
node ring colourThe same family at full strength. This is the channel that actually distinguishes eight families; the pale fills cannot.
node ring widthMerge depth — how many subgraphs attest to that node. Thin is one witness; thickest is eight or more.
+ at the arrowheadPositive relation
− at the arrowhead, red lineNegative relation
heavy dotted edgeUnsigned — no polarity recorded. Not a claim that it is positive.
dashed edgeDelay

The sign is a glyph, not merely a colour, and it sits at the arrowhead because that is what it is about: what this edge does to its target. Sign carried by colour alone fails for red-green colour blindness, in greyscale print, and on a washed-out projector.

Unsigned edges are drawn heavier than signed ones. Partly optical — a dotted line reads thinner than a solid one of the same nominal width — and partly because an unsigned edge is unfinished work, so it should not be the quietest thing on the canvas. Sign one and the extra weight drops away by itself; the width is derived from polarity on every render, never stored, so an edge cannot get stuck heavy.

Families come from families.js. Nodes whose schema label is not in that file stay grey rather than being herded into one bucket — the Composer keeps working on graphs that know nothing of this taxonomy.

Canvas colour

Five presets and a colour picker. The choice drives the drawing, the pane behind it, and the exported JSON, so a composite opened in the Graph Tool lands on the background it was composed against.

Edge ink follows the background automatically — on a dark canvas it flips to light, because edges and their labels sit directly on the canvas with nothing behind them. Node text does not follow: it sits on a pale family fill that stays pale whatever the background. Negative red also stays put, being the one edge colour that carries meaning rather than merely legibility.

The family palette was measured against the default #f5f4f1. Far from it the ring contrasts drift, and the hint line under the swatches says so.

Layout offers the Graphviz engines: dot (hierarchical), neato, fdp, circo, twopi, sfdp.

Two gestures on a node

GestureWhat happens
ClickOpens the node's details — its type and every property.
Click and hold (about half a second)Highlights that node's neighbourhood: its edges thicken and keep their colours, its neighbours stay bright, and everything else fades back. The status line reports how many edges and neighbours it found. Release to clear, or press Esc.

The hold gesture comes from the Graph Tool, where a long-press thickens the edges touching a node. It matters more here. A composite of a dozen subgraphs is much denser than anything drawn by hand, and the question you actually have in front of a composite — what does this shared node connect? — is the hardest one to answer by eye. Holding a merged gold node shows you, in one gesture, everything the pieces joined it to.

Because the highlight lasts only while you hold, it is safe to use while talking over a projected diagram: press, point, release. Nothing is selected, nothing changes, and the drawing returns to normal on its own.

Move off the node and the hold is cancelled — that is a pan, not a question. Drifting within the node is fine; panning is frozen for the length of the hold so the drawing cannot slide out from under the gesture. Re-composing clears any highlight along with the old drawing.

8 · Getting results out

  • Open in Graph Tool ↗ — converts the composite and opens it in the Graph Tool in a new tab, already laid out exactly as you see it here. Nothing to save, nothing to load. This is the one you want.
  • Export Graph Tool JSON — the same conversion as a file, for when you want to keep it or send it. Loads with the Graph Tool's JSON import, and still re-loads into the Composer.
  • Export Ward JSON — Ward's graph.js serialisation. For working against that library. This one does not open in the Graph Tool — see below.
  • Export DOT — Graphviz source, for anywhere that renders DOT.
  • Clear all — empties the beam.

The intended round trip: draw pieces in the Graph Tool → assemble in the Composer → open back in the Graph Tool → dress it for an audience.

Why Ward JSON doesn't open in the Graph Tool

These are two different formats, and always were. Until this was fixed, the Composer's only JSON export was Ward's, which the Graph Tool cannot read — so "export and open it in the Graph Tool" quietly did not work.

Composer (Ward's Graph)Graph Tool (RCN native)
nodes / relsnodes / edges
rel.from / rel.toedge.src / edge.tgt
identity is the array indexid is an explicit string
node.type is what it isschemaLabel is what it is; label is what we call it
no geometry at allx, y, w, h all required
visuals live inside propsvisuals live at the top level

The missing geometry is the real blocker. The Graph Tool's sizing routine only ever grows a node's width and height — it does not create them — so a node arriving without a w paints as a bare floating label. Ward's format has no coordinates because Graphviz was always doing the layout.

Which is also the answer. The composite on your screen has already been laid out, so the converter reads the positions straight back out of the rendered drawing. What lands in the Graph Tool is what you were looking at — same arrangement, same gold merged nodes, and the source subgraph names in the model title.

One subtlety: the family fill and the ring weight are facts about that composite and this taxonomy, not about the node. The export bakes them in so the Graph Tool shows what you were looking at, but marks them as synthesised. Load that file back into the Composer and they are dropped, so a node cannot keep a family fill in a drawing that knows nothing of families, nor a thick ring in a composite where it no longer merges. The canvas colour travels too.

9 · Making nodes merge — the identity rules

This is the part worth understanding properly. Four fields, four questions:

FieldQuestionIdentity?
labelWhich aspect of it moves?At variable level and below
schemaLabelWhat is it, in the schema?Yes, at every level
props.nameWhich one, if several?At instance level
extraLabelsWhat else is it called?No — aliases

The merge key grows one field at a time as you zoom in — see Detail. At variable level, the default, it is schemaLabel + label.

A variable label usually lives in several files. Fourteen of the 25 EIP labels do: Effectiveness of ORG appears in 9 of the 16 subgraphs. Rename it in one file only and the key stops matching, so that concept silently splits in two — and it will look like a modelling change rather than a typo. Search and replace across the whole folder.

Unnamed means "the type itself"

"?", "" and a missing props.name are all treated as the same UNNAMED value. So:

  • Drawing a schema — one Person, one Org. Names blank. The schema label alone is the whole identity.
  • Drawing a real neighborhood — three orgs. Schema label says Org; the instance name says which.

A minimal node

{
  "id": "n0",
  "label": "THE CLINIC",          // what it's called here — free
  "schemaLabel": "Org",           // what it IS — identity
  "extraLabels": ["Org"],         // aliases, exported to Neo4j
  "props": { "name": "Superior Community Clinic" },
  "x": 100, "y": 100, "w": 110, "h": 60, "shape": "ellipse"
}
Why not just use extraLabels? Because it's a list, and a list can't be an identity — any rule for picking an element is arbitrary and order-dependent. Two RCN aspect files already disagree on order (["Action","Active Goal"] versus the reverse). Aliases are real and worth keeping; they just aren't what a node is.

10 · The canonical sources — what to edit

Neither the family diagram nor the schema diagram is a file. Both are computed views — the Composer contracts whatever is in the beam at render time. There is nothing to open and edit. What is canonical lives one layer down.

The Composer fetches exactly two files by itself:

FileSuppliesTo apply a change
tools/families.jsFamily membership, colours, legend order, and the note arguing each assignment↻ reload families.js under the legend — works from disk too, it re-injects the script rather than fetching
tools/graph-sets.jsWhich sets appear as buttons, and their filenamesReload the page
tools/eip-aspects-variabilized/*.jsonEvery node, edge, verb, sign and variable labelClick the set button again

tools/eip-schema-cld.json — the signed CLD — is not read by the Composer. It is a separate authored artifact, useful as the reference for what the signs should be, but nothing live depends on it.

11 · When it doesn't do what you expect

Two nodes that should be one

Check, in order:

  1. Does the typed stat show everything typed? If it's amber, some node is identifying by its display label.
  2. Do both nodes have the same schemaLabel? Case and spacing count.
  3. Do both have the same props.name? Remember blank, "" and "?" are all the same, but "Clinic" and "clinic" are not.
  4. Hover the shared badge on the unticked one. If it doesn't list the node you expect, they aren't matching.
This is the failure to watch for, because it is silent. Sixteen RCN aspect files once composed to 30 nodes instead of 25 — five entities each split in two — because one file omitted props.name where the others had "?". Nothing errored. The drawing just quietly described a world with two Persons in it.

Everything collapsed into one node

The opposite failure. If several genuinely different things share a schema label and none has an instance name, they are — by the rule — the same thing. Give them props.name values.

Click-and-hold does nothing

The hold is about half a second, and it cancels only if the pointer leaves the node — drifting inside it is fine. If a highlight never appears on any node, check that something is actually composed: the gesture works on the drawing, not on the beam.

This was genuinely broken until July 2026, and not intermittently — it could never fire at all. The pan/zoom library calls preventDefault() on pointerdown, which by specification suppresses the compatibility mouse events, so over the canvas the browser fires pointerdown and then click and never mousedown — which was the event the gesture listened for. The click then fell through to the details panel, which is what "does nothing" looked like. It now listens on pointer events, which also brings touch and pen.

Everything is dotted

Dotted means unsigned, and most edges in a corpus usually are. Signs live in the CLD; port them onto the subgraphs and the edges go solid and thin. Note that family and schema level are never dotted — polarity is undefined there by design, so they stay solid.

All the nodes are grey

families.js did not load, or the graph's schema labels are not in it. The legend says which. Grey is the honest fallback, not a failure — the Composer does not assume any particular taxonomy.

A concept split in two after an edit

Almost always a variable label changed in one subgraph but not the others. See the warning in §9.

Nothing highlights

Either there's genuinely no overlap, or nothing is ticked. The highlight is relative to your current selection, and ticked rows never highlight themselves.

A subgraph won't load

Open the browser console. Failures are logged with the filename. The usual causes are an empty nodes array or edge endpoints that don't match any node id — edges referencing missing nodes are dropped silently.
