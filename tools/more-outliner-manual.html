More MORE

Browser-based outliner — inspired by Dave Winer's MORE 3.0

What is More MORE?

More MORE is a single-file, browser-based outliner. No server, no account, no installation. Open the HTML file, start typing. Everything runs locally in your browser.

An outliner organizes ideas as a hierarchy of nodes. Each node is a line of text. Nodes can have children (indented below them), and children can have their own children, to any depth. You expand and collapse branches to focus on what matters right now.

Autosave

Your work is saved automatically to browser storage every time you make a change.

Comments

Attach a private note to any node. Toggle all comments on or off globally.

Clones

Link copies of a node across the outline. Edit any instance and all update together.

Hoist

Zoom into any subtree. Everything outside it disappears until you dehoist.

Four export formats

Markdown, styled HTML, OPML, and FedWiki JSON. Plus print to PDF.

Rich text

Bold, italic, underline, and font color — applied to any selection inside a node.

Images

Embed images as nodes. Drag-and-drop or use the Image button. Resize inline.

Search

Find text across all nodes and comments. Navigate matches with ↑ ↓ or Enter.

Present

Turn any outline into a slide deck with one click. Print all slides to PDF.

The Interface

The screen has three zones:

Header bar

The More MORE logo at the left. To its right, the toolbar: a row of buttons for document-level actions. At small window sizes or high zoom the buttons wrap to a second line — the logo stays fixed and never overlaps them.

Sidebar

The left panel holds display controls: Numbering, Font, and Spacing. These affect appearance only and do not change the data.

Editor area

The main working area. The document title is at the top, followed by the outline. Each node is a text field; children are indented beneath their parent.

Autosave

More MORE saves your entire document to browser local storage automatically on every change — outline edits, comments, title, font, spacing, expand/collapse state. When you reopen the file in the same browser, your last session is restored instantly.

Note
Local storage is tied to the browser and device. It does not sync across machines. Use Save (JSON download) to back up or transfer your work.

Starting a new document with 📄 New clears local storage for that slot.

Nodes

Every line in the outline is a node. Click any node's text area to edit it. The textarea expands automatically as you type.

Adding nodes

ActionHow
Add a sibling belowShiftEnter — the cursor moves to the new node
Add a new top-level section+ Section button in toolbar
Add a child to any nodeHover the node → click + Child

Deleting nodes

Hover a node and click Delete. This removes the node and all its children. Use Undo immediately if you delete by mistake.

Keyboard Shortcuts

KeysAction

ShiftEnterAdd a new sibling node below; cursor moves to it
Shift↑Move focus to the previous visible node (cursor goes to end)
Shift↓Move focus to the next visible node (cursor goes to start)

Tip
Shift↑ and Shift↓ let you move through the entire visible outline without lifting your hands from the keyboard.

Indent & Outdent

Indent makes a node a child of the node immediately above it. Press Tab while editing, or use the hover action buttons.

Outdent promotes a node one level up in the hierarchy. Hover a node at depth > 0 and click ← Outdent.

Note
You can only indent a node if there is a node directly above it at the same level to become its parent. Top-level nodes (depth 0) cannot be outdented further.

Moving Nodes

Hover a node to reveal ↑ and ↓ action buttons. These swap the node with its sibling above or below within the same parent. Children move with the node.

Drag & Drop

Every node has a drag handle (⋮⋮) on its left edge, visible on hover. Drag it to reposition the node anywhere in the outline.

Where you are within the target row's height determines what happens on drop:

Cursor position on target rowVisual cueResult
Top third of rowOrange line above rowInsert before the target (same level)
Middle third of rowGreen highlight on rowMake the dragged node a child of the target
Bottom third of rowPurple line below rowInsert after the target's parent (one level up)

A dashed drop zone at the bottom of the outline (purple when active) moves the node to the very end of the document.

Comments

A comment is a note attached to a specific node. It appears inline below the node text in italic gray with a left border.

Adding a comment

Hover a node and click + Comment. A text area opens below the node text. Type your note there.

Removing a comment

Hover a node that has a comment and click − Comment. The comment is cleared.

Hiding all comments

Click 💬 Hide Comments in the toolbar to hide all comments globally. Click 💬 Show Comments to bring them back. The toggle affects display only — comments are preserved.

Tip
Use comments for context, sources, or questions that belong to a node but shouldn't appear in an exported document. The Markdown and HTML exports include comments; you can strip them by hiding before export if desired.

Clones

A clone is a linked copy of a node. All instances of a clone share the same text — editing any one updates all of them simultaneously.

Creating a clone

Hover a node and click ⚡ Clone. A copy appears immediately after the original. Both show a purple ⚡ badge with an instance count.

Working with clones

Edit the text in any instance. All instances update at once. Children of a clone are not shared — each instance has its own independent children.

Note
Clone linkage is preserved in JSON save files and OPML export (as a _note="clone:ID" attribute). It is not preserved in Markdown, HTML, or FedWiki exports, which render a snapshot of the text.

Expand & Collapse

Any node that has children shows a small + / − toggle button. Click it to show or hide that node's children.

Bulk expand / collapse

  • Expand All — expands every node in the outline
  • Collapse All — collapses every node
  • The +/− button beside the document title toggles only the first level

Expand/collapse state is saved with the document (both autosave and JSON save).

Hoist

Hoist is a focus mode. It promotes any subtree to become the entire visible document — everything outside it disappears. This is essential when working deep in a large outline where the surrounding structure has become noise.

Hoisting a node

Hover any node that has children. A ⬆ Hoist button appears in the action row. Click it. The outline now shows only that node's children. The document title area displays the hoisted node's text.

Navigating while hoisted

A breadcrumb strip appears above the title, showing the full path from the document root to the hoisted node:

Hoisted:   Document  ›  Section 2  ›  Subsection 3

Click Document or any crumb segment to jump back to that level. Click Dehoist on the right to return to the full outline.

Tip
Hoist does not change any data. It is purely a view filter. You can edit, add, delete, and rearrange nodes normally while hoisted.

Image Nodes

Images are first-class nodes. They can be positioned anywhere in the outline, moved, indented, and deleted like text nodes.

Inserting an image

Click 🖼 Image in the toolbar. A file picker opens — select any PNG, JPG, SVG, or other image file. The image is embedded directly in the document as a data URI (no external URL needed).

Alternatively, drag an image file from your desktop or file manager and drop it anywhere in the editor area. The image node is appended at the end of the outline.

Image controls

Each image node shows three controls below the image:

ControlWhat it does
Alt text / captionEditable text field. Used as the alt attribute in HTML export and as the image caption.
Width sliderDrag to resize the image from 80 px to 900 px wide. The current value is shown to the right.
Delete / ↑ / ↓Remove the image node or swap it with a sibling.
Tip — SVG images
Double-click an embedded SVG to open it in a new browser tab at full resolution.
Note
Images are saved in the JSON file as embedded data URIs, so the file size grows with the image. Image nodes are skipped by Search. They are included in HTML export as inline <img> tags but are not included in Markdown, OPML, or FedWiki exports.

Rich Text Formatting

The toolbar's leftmost group of buttons applies rich text formatting to selected text inside any node.

ButtonFormat applied
BBold
IItalic
UUnderline
A (color)Font color — opens a color picker

Applying formatting

Select text inside a node (click and drag, or Shift-click), then click the format button. The formatting is applied immediately. Click the same button again on a formatted selection to toggle it off.

Font color picker

Clicking the A button opens a popover with 20 preset colors (aligned with the Microsoft Word standard palette). Click any swatch to apply it. A More input at the bottom opens your browser's native color picker for any custom hue. The underline of the A shows the last-used color.

Note
Rich text formatting is stored as HTML inside the node and is preserved in JSON saves and HTML export. Markdown export converts bold and italic to **/* syntax; underline and color are stripped. OPML and FedWiki exports use plain text.

Search

Click 🔍 in the toolbar, or press ⌘F / Ctrl F, to open the search bar.

How search works

Type in the search box. Matching nodes are highlighted immediately (case-insensitive). The bar shows a counter: n / total. The current match is scrolled into view and highlighted in a distinct color.

Search covers both node text and comments. Image nodes are skipped.

Navigating matches

ActionHow
Next matchClick ↓ or press Enter
Previous matchClick ↑
Close searchClick ✕ or press Escape

Document Title

The large text field at the top of the editor area is the document title. Click it to edit. It expands automatically with long titles.

The title is used as the filename root when exporting (Markdown, HTML, FedWiki) and appears as the heading in exported documents.

The +/− square button to the left of the title collapses or expands all first-level nodes at once.

Custom spacing

Click Custom in the sidebar to reveal three sliders:

  • Node Margin — space above and below each node (0–30 px)
  • Text Padding — internal padding inside each node's text area (0–30 px)
  • Line Height — line spacing within node text (0.9–2.5)

Save & Load

Save (JSON)

Click 💾 Save. A JSON file downloads to your machine. It captures the complete document state: all nodes, comments, clone linkage, expand/collapse state, display settings, and a timestamp.

Filename format: more-outline-[timestamp].json

Load

Click 📂 Load and pick a previously saved JSON file. All state is restored, including display settings.

Note
Loading a file replaces the current document. The old document is not automatically saved. If you have unsaved work you want to keep, save it first.

New document

Click 📄 New. If the current document has content, you are prompted to save it first. The outline resets to a blank document and autosave storage is cleared.

Markdown Export

Click Export MD. A .md file downloads.

Format rules

Outline depthMarkdown output
Document title# Title
Level 0 (top-level nodes)# Heading
Level 1## Heading
Level 2### Heading
Level 3 and deeperIndented bullet - item
Comment on any node> blockquote on the line below

HTML Export

Click Export HTML. A self-contained .html file downloads with embedded CSS.

The file uses a proper heading hierarchy (h1–h3) matching outline depth, with deeper levels as indented paragraphs. Comments appear as italic gray left-bordered paragraphs. Inline markdown (**bold**, *italic*) is converted to HTML tags.

The exported file pastes cleanly into Word or Google Docs with formatting intact.

OPML Export

Click Export OPML. An OPML 2.0 .opml file downloads. OPML is the standard interchange format for outliners — it can be opened in OmniOutliner, Bike, WorkFlowy, and most other outliners.

Clone linkage is preserved as a _note="clone:ID" attribute on each cloned outline element. Comments are not currently included in OPML.

FedWiki Export

Click Export FedWiki. A .json file downloads, named from the document title (slugified). Drop it into a Federated Wiki's .wiki/pages/ directory to publish the outline as a page.

Output structure

Outline elementFedWiki item type
Top-level node (depth 0)paragraph — text in bold
Nested node (depth 1+)html — indented paragraph
Comment on any nodehtml — italic gray, left-bordered, indented one level deeper than its node

The JSON also includes a minimal journal entry (create action) so FedWiki recognises it as a valid page.

Print

Click 🖨 Print. Your browser's print dialog opens. The toolbar, sidebar, action buttons, drag handles, and expand toggles are all hidden in the print view — only the document title and outline content print.

To save as PDF, choose "Save as PDF" in the print dialog.

Presentation Mode

Click Present. You are prompted for a depth (1–10, default 2). Enter the number of outline levels you want on each slide.

How slides are built

Each top-level node becomes one slide. Its title is the node text. Its bullet points are collected from the children down to the chosen depth. If a slide would have more than six items, it splits automatically into continuation slides with a "(Continued)" label and "→ Continued…" footer.

Navigating slides

Use the ← Previous and Next → buttons. The counter shows the current slide, total slides, and the depth in use.

Printing the deck

Click 🖨 Print PDF inside presentation mode. All slides print one-per-page. Exit presentation mode with the Exit button.

Data Model

Every node in the outline is a JavaScript object. Text nodes and image nodes share a common base, with image-specific fields added for images.

Text node fields

FieldTypeDescription
idNumberUnique integer assigned at creation
textString (HTML)Node content; may contain rich text HTML (<strong>, <em>, <u>, <font>)
cloneIdNumber | nullnull = not a clone; integer = shared clone group ID
commentStringEmpty string = no comment; non-empty = attached note
childrenArrayOrdered list of child nodes (recursive)

Image node fields

FieldTypeDescription
idNumberSame as text nodes
typeString"image" — distinguishes image nodes from text nodes
srcStringData URI of the embedded image (e.g. data:image/png;base64,…)
altStringAlt text / caption
widthNumberDisplay width in pixels (80–900)
cloneIdNumber | nullSame as text nodes
commentStringSame as text nodes
childrenArraySame as text nodes

The JSON save file captures the full outline array plus display state: expanded map, style, font, spacing, custom spacing values, comments visibility, title, nextId, nextCloneId, clones map, and a savedAt timestamp.

Note — What is not saved
Undo history is not persisted. After reloading, undo starts fresh from the restored state.
