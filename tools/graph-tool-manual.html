Graph Tool — User Manual

Complete reference for all features

v22 Updated July 8 2026  ·  Introduction & comparisons →
Getting Started

1. Interface overview

The tool is a single HTML file. Open it in any modern browser — no install, no server, no internet connection required (after the initial load, which fetches the D3 layout library from a CDN).

The interface has three areas:

  • Canvas — the drawing area, left side. Pan and zoom freely.
  • Right sidebar — model name, graph mode, controls, properties panel, import, and export.
  • Properties panel — appears in the sidebar when a node or edge is selected. Shows all editable fields for that element.

The sidebar is divided into color-coded sections: the green Import band and amber Export band at the bottom make it easy to find the data exchange controls at a glance.

The tool contains built-in example graphs. Click Examples in the Import section to explore them — each loads into a fresh canvas (undoable).

3. Model name

The Model Name field at the top of the sidebar sets the filename used for all downloads (JSON, SVG, PNG, MDL, DOT, XMILE). Set it before exporting. It accepts letters, numbers, spaces, hyphens, and underscores.

Drawing

4. Nodes

Adding a node

Click + Node in the sidebar, then click anywhere on the canvas to place it. The tool immediately returns to Select mode — one node per click. To place multiple nodes, click + Node again each time.

To place many nodes in a row without clicking + Node each time, press n on the canvas. This enters sticky Node mode — the tool stays in Node mode after each placement. Click empty canvas to place, press Escape or click a different mode button when done.

Double-tap (or double-click) a new node to enter its label.

In-place editing

Double-tap any node to open the in-place editor. Type the label; press Enter to commit or click elsewhere. The node automatically resizes to fit the text. Multi-line labels are supported — use Shift+Enter to insert a line break.

Shapes

Available shapes: ellipse, rect, rounded (default), diamond, hexagon, cylinder, barrel. Select a node and choose a shape in the Properties panel.

Fill color

80 preset colors shown as a palette in the Properties panel. Click any swatch to apply. A custom color picker at the bottom of the palette accepts any color. Selecting multiple nodes and changing fill color applies the change to all of them.

Border

Three border controls in the Properties panel:

  • Color — custom picker, defaults to a darkened version of the fill color
  • Style — solid, dashed, or dotted
  • Thickness — slider (1–6px)

Font

  • Font size — per-node slider
  • Font color — 16-color palette; auto selects dark or light based on fill

Resize

Select a single node in Select mode. Eight handles appear around it. Drag any handle to resize. Resizing is symmetric: dragging the right edge also moves the left edge equally, keeping the center in place. Minimum size: 40×40px.

Multi-label nodes (Neo4j)

Nodes can carry multiple Neo4j labels. The first label appears as the primary node text. Additional labels (e.g. :Person:Employee) are entered in the Extra labels field in the Properties panel, separated by colons. They render as small italic text below the primary label and export in Cypher as CREATE (n:Primary:Extra1:Extra2 {...}).

Notes

The Note field in the Properties panel (always visible at the top of the panel) stores a free-text annotation. Notes appear in hover tooltips with a 📌 icon. They survive all import/export round-trips except MDL (Vensim does not have a note field).

Key/value properties

Below the note field, add arbitrary key/value properties to any node. Click + Add property. Each property row has ↑↓ reorder buttons and a delete button. Properties export to Cypher as node attributes and to DOT as node attribute strings.

URL properties

Any property value beginning with https:// or http:// is automatically rendered as a clickable ↗ link in hover tooltips and in the Properties panel. Links open in a new tab. This is Neo4j-compatible — the value exports as a plain string property.

Hover tooltips

Hover over any node to see its note and properties in a frosted-glass tooltip. To disable tooltips, check no hover in the Properties panel header.

5. Edges

Adding an edge

  1. Click + Edge in the sidebar.
  2. Click the source node (it highlights).
  3. Drag to the target node and release.

The tool returns to Select mode after each edge. To add multiple edges, click + Edge again.

To draw many edges in a row without clicking + Edge each time, press e on the canvas. This enters sticky Edge mode — after each completed edge the tool stays in Edge mode ready for the next. Clicking on empty canvas or a missed drop exits back to Select mode. Press Escape to exit at any time.

Clicking on empty canvas in Edge mode cancels without adding an edge.

Self-loops

Drag from a node back to itself to create a self-loop.

Straight vs curved

Edges default to straight. Toggle Curved or Straight in the sidebar to change all edges at once. To change individual edges, select the edge and toggle in the Properties panel.

Reshaping curved edges

In Select mode, drag the midpoint of a curved edge to move the bezier control point. A hint appears at the bottom of the canvas. Double-click a curved edge to reset its curve to the default arc.

Polarity

In the edge Properties panel, set polarity to + (reinforcing) or − (balancing). The polarity mark renders near the arrowhead. Polarity exports to Cypher as a property, to MDL as the Vensim polarity field, and to XMILE.

Polarity is central to CLD mode. Set it before switching to CLD to get accurate loop detection.

Delay mark

Check Delay in the edge Properties panel to add a delay mark (double bar) to the edge. Delay exports to MDL correctly and persists in JSON round-trips.

Dash style

Edge style options: solid (default), dashed, dotted. Select in the edge Properties panel.

Color

10 preset edge colors with names (Charcoal, Red, Orange, Gold, Green, Blue, Purple, Pink, Teal, Navy). A custom color picker is also available. Edge color exports to DOT as a named or hex attribute and persists in all JSON round-trips.

Thickness

Slider in the edge Properties panel (1–6px). Also available for bulk change on multi-selection.

Edge labels

Enter a label in the Relationship type field in the edge Properties panel. Use Enter in that field to insert a line break in the label.

Two global label orientation modes (sidebar toggles):

  • Horizontal — all labels render horizontally regardless of edge direction
  • Wrap — labels auto-wrap at ~16 characters on word boundaries

Per-edge overrides are available in the edge Properties panel.

Edge label font color

Separate from edge line color. Set in the edge Properties panel. Auto matches the edge line color.

Edge notes and properties

Same as nodes: free-text note and key/value properties, both shown in hover tooltips.

Sequential edge adding

Press e on the canvas to enter sticky edge mode. After each successfully drawn edge the tool stays in Edge mode, ready for the next one. Clicking on empty canvas or pressing Escape exits back to Select. Clicking + Edge in the toolbar (instead of pressing e) is still one-shot — it returns to Select after each edge.

Drawing

5b. Free lines & annotations

+ Line and + Arrow in the toolbar draw lines that are not connected to nodes — they are purely visual annotations. Use them for grouping brackets, call-out arrows, dividers, and other labels that belong on the canvas but not in the graph data.

Drawing a line or arrow

  1. Click + Line (no arrowhead) or + Arrow (arrowhead at end) in the topbar.
  2. Click and drag on the canvas to set start and end points.
  3. Hold Shift while dragging to snap to 45° angles.
  4. Release — the tool returns to Select mode.

Properties

Click a free line to select it. The Properties panel shows:

PropertyOptions
ColorCustom color picker
WidthSlider (1–6px)
DashSolid, dashed, dotted
ArrowheadNone (—), → (end), ← (start), ↔ (both)
LabelText field; label renders at the midpoint of the line

Moving and editing

Drag the body of a selected line to move it. Drag either endpoint to reposition just that end. Double-click a free line to open the in-place label editor.

Free lines are saved in JSON and appear in SVG and PNG exports. They are not part of the graph data — they do not export to Cypher, MDL, or DOT.

7. Graph modes overview

The Graph Mode section at the top of the sidebar switches between six analytical framings of the same graph. Switching modes does not alter the graph data — it changes what overlays and controls are active.

8. CLD mode — loops & propagation

CLD mode activates when you click CLD in the Graph Mode section. A purple banner appears at the top of the canvas.

Automatic loop detection

On entry to CLD mode, the tool automatically traces all feedback loops in the graph and classifies each as R (Reinforcing) or B (Balancing), based on the product of edge polarities around the loop. Labeled circular badges appear on the canvas — yellow for R, blue for B, grey for undetermined (missing polarity data).

Click a loop label to highlight the edges in that loop. Click again or click empty canvas to clear.

A Loop labels toggle button appears below the mode buttons whenever CLD is active. Click it to suppress all loop label badges — useful when presenting or when the labels obscure the diagram. Click again to restore them. The button is active (purple) when labels are visible and dimmed when suppressed.

When a single node is selected in CLD mode, a collapsible list appears below the Loop labels button showing every loop that node belongs to, with R/B type badge and loop name. Click the header row (showing the node name and a ▼/▶ chevron) to collapse or expand the list.

Long-press polarity propagation

  1. In CLD mode, long-press any node (hold ~600ms). A popup appears with ↑ and ↓ buttons.
  2. Choose ↑ (increasing) or ↓ (decreasing) as the initial perturbation.
  3. The tool animates the causal effect rippling outward hop by hop — green for reinforcing, red for balancing — following edge polarities.

A control panel appears at the bottom-right of the canvas with:

  • Speed — 100ms to 1200ms per hop
  • Serialized — when checked, each hop completes before the next begins (clearer for teaching)
  • ↺ Replay — replay the propagation from the beginning
  • Space — pause or resume

Shift+long-press — edge highlight

Shift+long-press a node to highlight all edges directly connected to it (incoming and outgoing), rendered in their assigned colors. Releases on mouse up.

Set polarity on all edges before entering CLD mode. Edges without polarity contribute to loop detection but are counted as neutral, which can produce incorrect R/B classifications.

9. EIP mode

EIP mode overlays three labeled columns on the canvas representing the three domains of the Ecology–Institutions–Politics framework:

  • Ecology (green column, left)
  • Institutions (purple column, center)
  • Politics (blue column, right)

A color palette appears in the Properties panel with pre-assigned colors for each domain. Click an EIP color swatch to apply it to the selected node(s) and visually anchor them in the appropriate column.

The column positions are visual guides — there is no automatic snapping. Arrange nodes intentionally within the columns. The EIP column layout and node colors export normally to SVG and PNG for presentation.

EIP column positions scale with the canvas zoom and pan. The proportions stay consistent as you zoom in to work on a section of the diagram.

9b. NRM mode — Neighborhood Risk Management

NRM mode implements the Tripod Beta accident causation model, adapted for neighborhood risk analysis. An orange banner appears at the top of the canvas when active.

Node types

The Properties panel shows a color-coded palette organized into three groups. Click a type to make it active — the banner updates to confirm. Click anywhere on the canvas to place a node pre-labeled and pre-colored for that type. The tool remains in that type until you click a different one.

GroupTypes
Causal Chain Underlying Cause (dark red) → Precondition (orange) → Immediate Cause (salmon). Reads left to right, roots to event.
Incident Trio Agent (yellow), Object (light green), Event (pink). One Agent and one Object per Event. Combination nodes (Event/Agent, Event/Object) handle cases where an Event feeds into a subsequent Trio.
Barriers Failed Barrier (blue), Missing Barrier (lavender), Intact Barrier (medium blue). Place on trajectories between Agent/Object and Event.
Other Narrative — a light grey clarification node attached to a connection.

Basic Risk Factors

Underlying Cause nodes can be further classified using Basic Risk Factor (BRF) codes (Annex 4 of the Tripod Beta standard): Hardware, Design, Maintenance Mgmt, Procedures, Error-enforcing Conditions, Housekeeping, Incompatible Goals, Communication, Organisation, Training, Defences. Add the BRF code as a node property or append it to the label.

Combining with CLD

NRM and CLD modes are mutually exclusive overlays, but the underlying graph is the same. A causal chain built in NRM mode can be switched to CLD mode to run polarity propagation — useful when the causal pathways also carry feedback dynamics.

Build the causal chain (Underlying Causes → Preconditions → Immediate Cause → Event) first, then add Barriers on the trajectories. Export SVG or PNG for reporting.
Analysis Modes

9c. Trace mode — pathway animation

Trace mode lets you mark edges as members of named pathways (T1, T2, T3, T4) and then animate each pathway in sequence. Use it to walk an audience through a causal chain, a process flow, a decision path, or a scenario.

Assigning edges to traces

  1. Switch to Trace mode in the Graph Mode section.
  2. Select one or more edges (click an edge, or shift-click for multiple).
  3. In the Properties panel, find the Trace path row.
  4. Click any combination of T1 / T2 / T3 / T4 — each button toggles membership independently. An edge can belong to multiple traces at once.
  5. Click ∅ to remove the selected edges from all traces.

Edges in multiple traces show stacked colored dots at their midpoint — one per trace, ordered T1→T4 along the edge direction.

Animating a trace

  1. In the sidebar Trace controls, click ▶ T1 (or T2/T3/T4).
  2. The animation propagates wave by wave along the assigned edges, lighting each edge then each target node.
  3. Use the Speed slider to control timing. Press Space to pause/resume.
  4. Click the ■ stop button or click the active ▶ button again to stop.
Traces are stored in the JSON export and survive round-trips. Old JSON files with single-trace edges (trace: 1) are automatically migrated to the multi-trace format on load.
Analysis Modes

9d. Wardley mode

Wardley mode renders a Wardley Map grid behind the graph. Node positions become meaningful: horizontal position encodes evolution stage (Genesis on the left, Commodity on the right); vertical position encodes value chain visibility (Visible at top, Invisible at bottom).

Importing from the Wardley Map Generator

  1. In the Wardley Map Generator, click Export Map Data to download a .json file.
  2. In the graph tool, click JSON in the Import section.
  3. Drag the .json file into the drop zone (or paste its contents) and click Load.
  4. The tool auto-detects the Wardley format, places all components on the correct grid positions, draws dependency edges, sets the model name, and switches to Wardley mode automatically.

The grid

The four evolution stages are delineated by vertical dividers with subtle background tints. Stage labels appear at the top and bottom of the grid. The grid lives in SVG space — it pans and zooms with the diagram.

StageApprox. x rangeMeaning
GenesisLeft 20%Novel, uncertain, rare — competitive advantage
Custom Built20–40%Emerging practices, custom solutions
Product40–65%Productized, established offerings
CommodityRight 35%Utility, widespread, well-understood
Dagre auto-layout is disabled in Wardley mode — it would scramble the positional meaning. Move nodes manually to adjust their evolution/visibility position.
Analysis Modes

9e. Legend

The Legend section in the sidebar (between Graph Mode and Properties) manages a color legend for the diagram. The legend can be shown as a frosted-glass overlay in the bottom-right corner of the canvas.

Auto-derive

Click Auto to scan all node colors and generate legend entries automatically. Known Wardley palette colors are labeled by their scheme name (User Needs, Services / Apps, Platform, Infrastructure, Genesis, etc.). Unknown colors are labeled with the first one or two node labels that use them.

When a Wardley JSON is imported, Auto runs automatically and the legend appears immediately.

Manual entries

Click + Add entry to add a blank entry. Each entry has a color swatch (click to open a color picker) and an editable label. Click × to remove an entry.

Show / Hide

Click Show to display the legend overlay on the canvas. The button toggles to Hide while the overlay is visible. The legend overlay is pointer-events-none — it does not block clicks on the canvas.

Legend entries and visibility are saved in the JSON export and restored on load.
Analysis Modes

9f. OPM mode — Object Process Methodology

OPM mode implements ISO 19450 Object Process Methodology (Dov Dori, 2002 / ISO 2015, 2024). Every edge drawn in OPM mode carries a typed relationship chosen from a picker, and an Object Process Language (OPL) sentence is generated automatically. The OPD (diagram) and the OPL (plain-text sentences) are mirrors of the same model — they cannot drift apart because they are generated from the same data.

Entering OPM mode

Click OPM in the Graph Mode section. A teal banner appears at the top of the canvas.

Node types

OPM has two node types. Select a type from the palette at the top of the Properties panel, then click the canvas to place it:

  • Object — things that exist; drawn as a rounded rectangle (blue tint)
  • Process — things that transform objects; drawn as an ellipse (green tint)

You can also assign or change the OPM type of any existing node by selecting it in OPM mode and clicking Object or Process in the Properties panel.

Drawing typed edges — critical step

In OPM mode, typed edges are drawn by clicking + Edge in the toolbar first, then dragging from source to target. You must use the + Edge button — dragging directly from a node in OPM mode creates an untyped edge with no picker.

  1. Click + Edge in the toolbar.
  2. Drag from a source node to a target node and release.
  3. A relationship picker appears — choose the link type.
  4. Click Apply. The tool returns to OPM mode.

When only one valid link type exists for a given source/target combination, it is applied immediately without showing the picker.

Link types

Ten link types from ISO 19450, grouped by relationship context. The picker shows only the types valid for the source and target node types you connected.

Structural relations (Object → Object)

The four structural relations cover different kinds of "is related to": is part of (composition), is a type of (class hierarchy), exhibits (attribute), is an instance of (individual in a class). Being forced to choose among them clarifies thinking that diagrams with unlabeled lines leave ambiguous.

OPL sentences panel

An OPL Sentences panel appears in the right sidebar in OPM mode. It is collapsed by default — click the header to expand it. The panel lists one auto-generated OPL sentence per typed edge and updates live as edges are added or nodes are renamed.

Example output for a neighborhood commercial district diagram:

  • City of Bellingham consists of On Street Business and Waterfront Businesses.
  • Restaurant is a type of On Street Business.
  • Bantam Restaurant is an instance of Restaurant.
  • Bantam Restaurant handles Ordering, Cooking, and Serving.

Note that when the same subject has multiple edges of the same type, they are combined into one compound sentence automatically.

Exporting OPM data

Three export buttons appear while OPM mode is active — in the Export section and in the OPL Sentences panel header:

  • Export OPL (in the OPL panel header) — exports a plain-text .txt file with Object and Process declarations followed by all OPL relation sentences, using compound sentences where the same subject has multiple relations of the same type.
  • OPM→Cypher — exports the OPM graph as Neo4j CREATE statements with typed nodes (:Object or :Process) and OPL-labeled relationships.
  • OPM→CSV — exports a CSV of triples: source label, link type, target label, OPL sentence.
OPM link types, markers, and node types are stored in the JSON export and restored on load. Switching back to Basic mode preserves all OPM annotations — you can return to OPM mode and continue where you left off.
Analysis Modes

9g. Layers

Layers let you assign a named category to any node or edge and then show or hide everything on that layer at once. Unlike graph modes, layers are a data annotation — they persist in JSON and are independent of which mode is active.

Assigning a layer

Select a node or edge. In the Properties panel, find the Layer field. Type any name — Financial, Physical, Information, or anything meaningful to your diagram. Press Enter or click elsewhere to commit.

Multiple nodes and edges can share the same layer name. Layer names are free-text — there is no predefined list.

Toggling layer visibility

As soon as any node or edge has a layer name, a Layers panel appears in the left sidebar. Each layer name is shown as a toggle button:

  • Button active (highlighted) — the layer is visible
  • Button dimmed — the layer is hidden

Click a button to toggle. Hidden nodes disappear from the canvas. Hidden edges disappear too. Edges whose source or target node is on a hidden layer are also hidden automatically — you do not need to assign the same layer name to both nodes and their connecting edges.

Persistence

Layer names are saved in JSON export and restored on load. Layer visibility state resets on load — all layers start visible.

Layers are useful when a single diagram covers multiple domains (e.g., Physical infrastructure and Financial flows). Assign each domain a layer name, then toggle between them to present one domain at a time without maintaining separate diagrams.
Analysis Modes

9h. Triples — reifiable edges

Triples make any edge a first-class entity that can itself be the target of other edges. This is the graph-theory equivalent of RDF reification: instead of only saying A → B, you can say C relates to the fact that A → B. Use it to attach agreements, interventions, barriers, trust ratings, or contested claims directly to specific causal links — without restructuring the underlying diagram.

Promoting an edge to a triple

  1. Select an edge in Select mode.
  2. In the Properties panel, find the Triple section.
  3. Check Create Triple — or press T while one edge is selected.
  4. A circle dot appears at the edge midpoint, labeled T01 (auto-incremented for each new triple).

To remove a triple: uncheck Create Triple (or press T again). If any meta-edges point to that triple, a confirmation prompt appears before removal.

Triple panel fields

Click a triple dot to select it. The Properties panel shows:

FieldDescription
Subject / Predicate / ObjectAuto-derived from the edge's source node, relationship label, and target node. Read-only display.
Triple labelEditable name for this triple. Double-tap the triple dot on the canvas to edit it in-place.
Statushealthy (green), degraded (amber), or broken (red). Indicates the current state of the relationship the triple represents.
StrengthA 0–1 slider. Records the perceived strength or confidence of the relationship.
NotesFree-text annotation for the triple — evidence, sources, caveats.
Meta-edgesLists all meta-edges pointing to this triple (node label → triple ID), each with a delete button.

Drawing meta-edges

A meta-edge connects a node to a triple dot — it says "this node relates to that relationship."

  1. Click + Edge (or press e for sticky mode).
  2. Click a source node to start the edge.
  3. Drag to a triple dot and release — the dot highlights when your cursor is within range.

Meta-edges render as dashed blue lines. They behave like regular edges for selection and deletion, and carry a label field in the Properties panel.

When a triple dot has at least one meta-edge, it renders slightly larger (hit radius 14px instead of 10px) to make it easier to target.

Visual indicators

  • Triple dot — a circle at the edge midpoint labeled with the triple ID (T01, T02…).
  • Node glow — when a node has a meta-edge pointing to a triple, a soft halo appears around it in the triples rendering layer.
  • Meta-edge count badge — shown inside the triple dot when there are incoming meta-edges.

Deletion

  • Deleting a triple dot removes the triple annotation from the edge and all meta-edges pointing to it.
  • Deleting an edge that is a triple also removes all its meta-edges.
  • Deleting a node removes all meta-edges sourced from that node.

Persistence

Triple data (all fields) and meta-edges are stored in the JSON export and restored on load. They are not currently exported in Cypher, MDL, or DOT formats.

Triples are most useful in knowledge-graph and governance work — attach a "contested" or "under review" annotation to a specific causal link, connect an intervention node to the relationship it targets, or record which agreement governs which dependency.

10. Driver trees

Driver trees provide a radial expansion view centered on a single node — showing what it affects, what drives it, or both. This feature is unique to the RCN tool.

Opening a driver tree

  1. Select a single node (any mode).
  2. A Driver Trees section appears in the right panel, between the mode buttons and the Loop labels button, showing the selected node's name.
  3. Click one of three buttons:
    Effects ▶ — what does this node affect (outgoing edges)?
    ◀ Causes — what drives this node (incoming edges)?
    ◀ Both ▶ — full upstream and downstream view simultaneously.

The Driver Trees section is hidden when no node (or multiple nodes) is selected. The tree view opens as a full-screen overlay over the main canvas.

Navigating the tree

  • Depth selector — controls how many hops to expand (1–6 or Full)
  • Repeated nodes — nodes that appear more than once are shown in yellow with [brackets]. Click a repeated node to highlight the first occurrence.
  • Polarity marks (+ or −) appear on connecting lines between nodes.
  • Click ← Back to return to the main canvas.
Use Full depth to see all paths, then reduce depth to clean up the view for presentation. The Depth selector rebuilds the tree instantly.

Exporting the tree as SVG

Click Export SVG in the tree toolbar (right side of the toolbar, beside the depth selector and legend key) to download the current tree view as a vector SVG file.

The SVG captures everything visible in the tree:

  • All node boxes — root (blue), repeated/bracketed (yellow), and normal (white) — with correct fill, border color, and rounded corners
  • Node labels, wrapped to the same line width as the screen layout
  • All connecting arcs and arrowheads
  • Polarity marks (+ in green, − in red) at the correct midpoints
  • The tree title as a caption

Background is white. The filename is generated automatically from the tree title — for example, a Causes tree for a node called "Sense of Coherence" downloads as causes-tree-sense-of-coherence.svg.

The Depth selector affects what is exported — set the depth you want before clicking Export SVG. A Causes tree, Effects tree, and Both view each export as independent SVG files with their own layout.

12. Node search

A search bar is always visible in the top-left corner of the canvas. Type to filter: matching nodes highlight in purple and non-matching nodes dim. The match count appears next to the search field.

Search matches on node labels, extra labels, and key/value property names and values (all case-insensitive, substring). Clear the field to restore normal view.

16. Tips & patterns

Working session pattern

  1. Set the model name first.
  2. Build the graph in Basic mode.
  3. Add polarity to all edges that represent causal relationships.
  4. Switch to CLD mode to check loop structure and animate propagation.
  5. Export JSON before closing the browser tab.

Using merge for modular diagrams

Build sub-diagrams as separate JSON files (one per subsystem). Use Merge to combine them. Shared nodes (same label) are unified — this is how you assemble a large system diagram from pieces without duplicating shared variables.

Neo4j workflow

Design your graph schema here, export Cypher, paste into Neo4j Browser. When you have data in Neo4j and want to visualize it, run a MATCH query and use the MATCH import button to bring the result back into the tool.

Vensim workflow

Sketch the causal structure here (faster than in Vensim), export MDL, open in Vensim to add equations and run simulations. When the Vensim diagram is updated, export MDL from Vensim and re-import here for analysis in CLD or EIP mode.

Sharing and archiving

For a quick share via link: use URL export and paste it — the full diagram is encoded in the URL, nothing to attach. For sharing as a file: use Snapshot — one .html file the recipient opens directly in any browser, diagram pre-loaded, no JSON companion needed. For archiving: keep a JSON export. It is the only lossless format and the only one that can be re-imported. SVG/PNG are for presentation only.

Large graphs

Above ~100 nodes, Force layout slows down. Use Dagre instead — it runs synchronously and handles large graphs well. Use Search to locate nodes quickly when the graph is dense. Driver trees are especially useful in large graphs: they let you focus on one variable's neighborhood without navigating the full diagram.

Presenting a diagram

Set a clean background color (white or off-white), export PNG at 2× for slide decks, or export SVG for documents where you need to scale without loss. Use Copy to paste directly into PowerPoint or Keynote without a file. Use Print to send the current viewport to the browser print dialog — useful for paper handouts or saving to PDF. The model name sets the filename, so name your diagram before exporting.
