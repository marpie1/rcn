RCN NDC Map

Introduction — what it is, what it does, and why it exists

Document updated: July 2026
Introduction User Manual Open the Map ↗
The RCN NDC Map is a single HTML file that puts all of the network's Neighborhood Development Centers on one interactive map — with their geographic context, community issues, and parcel-level data — in a tool that runs entirely in the browser with no server, no account, and no install.

Who it is for

The map was built for three audiences. RCN staff and researchers who need to understand the geographic, ecological, and institutional context of each NDC location — who can see all seven NDCs at once, zoom into any one, and compare the surrounding administrative boundaries and ecological zones. NDC organizers who want to track and communicate about specific community issues — zoning decisions, land use questions, neighborhood campaigns — with parcel-level specificity and a clear record of who holds what position. Funders and partners being introduced to the RCN who need a clear answer to "where are these communities and what are they working on?"

NDC locations

Nine Neighborhood Development Centers are built in to the map. Each has its own geographic context layer including administrative boundaries, ecological zones, and points of interest. You can also add your own NDCs (saved in your browser) — they behave the same as the built-ins.

What it does

Network overview

All 9 built-in NDCs (plus any you add) shown simultaneously as red circle markers. Click any marker for address and name. Legend organized by group bucket. One-click return to overview from any NDC view.

Per-NDC geographic context

Click any NDC in the sidebar to zoom in and load its geographic layers: admin boundaries (blue), ecological zones (purple), NDC zone polygons (red), copper mineral deposits (brown), and churches (violet).

Legend highlighting

Click any legend item to highlight just that feature and dim the rest. Shift-click to multi-select. The map zooms to fit the highlighted features. Click the same item again to clear.

Issue overlay

Each NDC can have community issues attached — zoning decisions, land-use questions, neighborhood campaigns. Clicking an issue loads parcel-level markers color-coded by stance: green (pro), red (con), grey (unknown).

Issue detail link

Each active issue shows a link to its full Issue Map — the dedicated issue-polygon-map.html tool for that issue, where parcels can be edited, annotated, and exported, and custom boundaries can be drawn, named, and renamed.

OSM geocoder search

OpenStreetMap Nominatim search built into the sidebar. Search any address, place name, or landmark worldwide. Results dropdown — click any result to fly to that location and drop a marker.

Basemap switcher

Seven basemap options: Light (default), OpenStreetMap Voyager, Satellite, Topo, CyclOSM, Transport, and Dark. Accessible from the top-left layer control on the map.

Static data, no server

All geographic data lives in rcn_static_data.js — generated once from the geo database and served alongside the HTML in the same folder (a two-file deploy). No API calls for NDC or place data. (A single-file "standalone" build inlines the data for handouts.)

Custom location pins

+ Add location button drops a pin anywhere on the map. Name it, and it's saved in your browser. Pins appear in the legend, support highlighting and zoom, and survive page reloads. An ✎ Edit link renames or recolours a pin any time.

Boundary layer builder

Search OpenStreetMap for any jurisdiction polygon (county, watershed, city limit), draw one freehand, or use the Claude prompt bridge to generate one. Added layers persist in localStorage.

Edit anything you make

Every custom boundary has an ✎ Edit editor — change its name, type, group bucket, colour, fill opacity, and which NDC it's filed under. NDCs and pins are editable too, so nothing you create is locked once made.

Nest boundaries under an NDC

A boundary's Under NDC field (in its Edit editor, and on the draw/paste forms) files it inside that NDC's section of the legend — reassignable any time, or set back to "My additions", without redrawing.

Editable NDCs

NDCs you add appear under Saved NDCs in the Add NDC panel with an Edit link — rename the name or fix its location text (handy if a stray URL lands in a field). Built-in NDCs stay fixed.

Group buckets, your labels

The old two-letter "code" is now a free-text group bucket (up to 32 characters, any case) — use a state, a country, or your own label like Whatcom or Nooksack. NDCs and boundaries that share the exact same bucket group together in the legend.

Publish regions (federation)

The Publish regions panel builds a regions.json roster — list each steward's exported region file, and it downloads the manifest for you to upload. The map then pulls every listed region in as read-only overlays, so a whole network of stewards' maps stitch together.

New issue panel

Fill in a title and NDC and click Create issue — the issue appears on the map immediately, no API key needed (the affected area defaults to the NDC; entered addresses become pro/con/unknown pins). Optionally, Draw area with Claude uses an Anthropic key to draw the real affected-area shape and infer stances.

Export my data

A top-level ⬇ Export my data (JSON) button bundles everything you've added — NDCs, locations, boundary layers, and corrections — into one file for backup or sharing. Per-dataset export buttons remain in the boundary panel's Saved tab.

Export the view (SVG / PNG / Print)

Save the current view: SVG or PNG download the vector overlays (boundaries, NDCs, pins, issue areas) on a plain background; Print uses the browser to print the full map with the basemap (choose Save as PDF). Basemap tiles can't go into SVG/PNG — only Print captures them.

One layer key, no clutter

Each NDC's layers live under its own collapsible header (expand for the key). Everything you add — custom boundaries, pins, federated regions — sits once in a "My additions & layers" section. Panels start collapsed.

How it differs from the alternatives

Google Maps / Apple Maps Different purpose

General-purpose navigation maps. They know nothing about RCN NDCs, community issues, geographic context layers, or parcel-level stances. You can drop a pin on an NDC address, but the map carries no network-specific meaning. The RCN map is the inverse: it knows exactly where every NDC is, what surrounds it geographically, and what issues the community is engaged with — but it is not for navigation or finding a coffee shop.

ArcGIS / QGIS Powerful GIS, wrong floor

Professional GIS tools that can do everything this map does and far more. The barrier is the floor: ArcGIS Online requires a subscription and a learning curve; QGIS requires a desktop install and file management. Neither produces a shareable single-file artifact that an NDC organizer can open on a phone or email to a city council member without explanation. The RCN map is designed for people who are not GIS professionals — one file, one click, no setup.

Google My Maps Easy to start, hard to own

Google My Maps makes it easy to drop custom pins and layers on a map. But the data lives in Google's infrastructure — not yours. There is no way to attach issue-specific parcel data with stance tracking, no way to bundle NDC-specific geographic context, and no way to export a self-contained file. The RCN map is fully owned: the HTML and data files live in the RCN repository, can be deployed to any host, and never depend on a third-party account.

issue-polygon-map.html Complementary — different scope

The issue-polygon-map.html tool focuses on a single issue in a single community: editing parcel polygons, drawing and naming custom boundary polygons, recording stances, adding notes, importing and exporting GeoJSON. It is the deep editing environment for a single issue's parcels. The RCN NDC Map is the interactive hub: you add locations, boundary layers, NDCs, corrections, and new issues there, and everything you add is saved in your browser and exportable to JSON. The one thing it does not do is edit an issue's parcels — for that it shows all issues across all NDCs in context and links out to the issue-polygon-map. The two tools are designed to be used together — edit an issue's parcels in the issue-polygon-map, publish to the NDC map.

What exists only here

  • Unique
    RCN network geography in one place. No other tool has the geographic context of all seven NDCs — admin boundaries, ecological zones, mineral deposits, NDC zone polygons — organized by site and ready to explore without any GIS expertise.
  • Unique
    Issue-to-parcel pipeline. Community issues are linked directly to parcel-level data: which properties are affected, who holds what stance (pro / con / unknown). This connection between a community campaign and its geographic specifics does not exist in any general-purpose mapping tool.
  • Unique
    Single HTML file, fully deployable. The map file and its data file can be hosted on any static server, opened locally from disk, or emailed. No server-side code, no database connection, no framework. The same file works as a development tool, a presentation, and a deployed public artifact.
  • Unique
    Offline-capable for NDC and place data. All NDC locations and geographic context data are bundled locally in rcn_static_data.js. Once loaded, the geographic layers work without an internet connection. Only the OSM search geocoder and issue JSON URLs (which are hosted externally) require network access.
  • Unique
    User-owned spatial data, stored locally. Custom location pins, corrected NDC positions, added NDCs, and added boundary polygons are all saved in your browser's localStorage. Nothing is sent to a server. One top-level "Export my data" button downloads all of it as a single JSON file for permanent backup.

Honest gaps

GapNotes
Issues require a hosted JSON URL Issue data is fetched from a URL at runtime — it is not bundled in the static data file. Someone must host the issue JSON (e.g., a FedWiki asset or any static server) before the issue layer can appear on the map.
Shared baseline data still lives in the source files You can add your own NDCs, locations, boundary layers, and issues directly through the UI — they save to your browser (localStorage) and export to JSON. What still requires editing the source is baking something into the shared baseline that ships to everyone: a permanent NDC goes in the NDC_LIST array (plus a static-data regeneration), and a permanent issue needs its JSON hosted (see above).
Mobile layout Designed for desktop. The sidebar is usable on a tablet in landscape; on a phone screen it is tight and the NDC accordion is harder to navigate.
Static data requires a regeneration step When NDC geographic boundaries or context layers change in the source database, generate_static_data.py must be re-run to rebuild rcn_static_data.js. There is no live connection to the geo database.

Positioning statement

The RCN NDC Map serves a function that no general-purpose mapping tool can: it holds the network's geographic intelligence in one place — who is where, what surrounds them ecologically and institutionally, and what community issues they are actively engaged with down to the parcel level. It is the network's front-facing spatial record and the operating context for every NDC's community work.

It is also a commitment to data ownership. The map requires no Google account, no ArcGIS subscription, and no cloud service. The data belongs to the RCN and lives in the RCN's repository. It can be deployed to any server, archived, forked, or handed off without dependency on any platform that could change its terms, pricing, or availability.
