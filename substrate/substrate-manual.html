1 · Starting it

Two things must be running: Neo4j Desktop (the RCN SCHEMA server) and the projection API.

cd ~/rcn/substrate

python3 db.py --check          # is Neo4j reachable, and what is in it
python3 api.py                 # projections + the tools, port 8768

Then http://localhost:8768/ lists every projection and the rendered views. The API also serves the tools, so everything is one origin and CORS never arises.

Claude Code has full admin over the database but cannot start or stop the DBMS. If db.py --check cannot reach the endpoint, open Neo4j Desktop and start the server by hand.

Credentials live in ~/rcn/.env.neo4j, mode 600 and gitignored. There is no driver dependency — db.py talks Cypher over HTTP with the standard library only, so the substrate has no install step.

2 · The three graphs

?db= selects which graph, never which query. All three are read by byte-identical Cypher, and that is the architectural claim being tested.

DatabaseContentsSources are
neo4jThe n=6 reference. 6 concepts, 6 states, 7 edges (5 causal, 2 structural), 2 instances. Hand-written in seed.py.people — merchant, organizer
composite26The signed EIP CLD. 25 concepts, 25 states, 57 edges (12 causal, 45 structural).topics
aspects16The 16 aspect drawings with exact provenance. 24 concepts, 25 states, 70 edges (20 causal, 50 structural), 17 with no relation family.topics
What a source is differs per graph, and no lens may infer it. Nothing in a list of strings separates merchant from action. Each loader declares it on the :Aspect registry as kind:'person' or kind:'topic'. Only on a person graph does size(sources) > 1 mean agreement; on a topic graph a high count means the concept is cross-cutting.
The two big graphs disagree about one thing, and it is worth knowing before the counts confuse you: composite26 holds Affect as two concepts, where aspects16 holds one concept with two states. That is why 25 concepts there and 24 here describe the same vocabulary.

3 · The lenses

Every projection returns the same envelope — the Graph Tool's native schema, so renderers read it with no translation. Note edges use src/tgt, never from/to.

EndpointWhat it answers
/projection/schemaThe substrate describing itself — node kinds, their properties, the relationships between them, with live counts. Derived, so it cannot go stale.
/projection/causalThe CLD reading. Its nodes are states, because a causal claim is about measured quantities.
/projection/structureThe ERD reading — part-of, is-a, acts-in, depends-on. Polarity is deliberately emitted as none: a structural relation is not the kind of statement that has a sign.
/projection/goldThe federation lens: who drew what, and where two hands met.
/projection/vocabularyFamily → concept → states as a tree. Feeds the Sunburst. Carries start/span fractions so the renderer stays dumb.
/projection/driversCausality unrolled from one state. ?root=X&dir=causes|effects&depth=N. Carries net, the sign accumulated along the path, and marks a node already on its own path as loop rather than following it.
/projection/subgraphsThe sixteen drawings, with concept and edge counts.
/projection/subgraph/<name>One drawing — exactly what a save would write.

A subgraph is not stored. WHERE 'org' IN c.sources is the drawing. The sixteen and their union are the same rows read two ways, which is the payoff of keeping sources as a list rather than a scalar — and it means nothing is duplicated to make both readings work.

4 · The round trip

tools/graph-tool-v22.html?url=/projection/subgraph/org   →  edit  →  "→ Substrate"

Loading by that URL records which drawing this is, so saving replaces the right one without being asked. Both stores move together, always:

PUT  /subgraph/org           the database
POST /subgraph/org/file      tools/eip-aspects-variabilized/org.json

Saving to the database alone would leave the file saying something else, and the next loader run would silently revert the edit. The file stays canonical so git keeps the history of a governance-grade artifact; the database is always rebuildable from disk.

Layout never passes through Neo4j. It travels file → tool → file. The substrate stores no coordinates by design, so a drawing that has never been placed gets a deterministic fallback ring — the ring is the fallback, not the answer.

GET /subgraph/<name>/file previews the JSON without writing it. Writing is a POST, because a GET that changes the world is a GET something will eventually prefetch.

Order is part of the diff. The database has no opinion about the order of a set, so emitting rows in Cypher order once rewrote whole files — 44 insertions for a one-character change, and a diff nobody reads. The writer keeps the file's own node and edge order, its ids, coordinates, colours and untouched props. Fixing one polarity now produces one changed line.

5 · Why a save cannot destroy work

PUT retracts, then re-asserts:

  1. drop this drawing from every sources list
  2. delete only what is left with no witness at all
  3. upsert what was sent, carrying this drawing's name

A concept another drawing also contains keeps its other witnesses and survives step 2. One contributor cannot delete another's work, even by saving an empty canvas. Gold recomputes for free, because it was never stored.

Verified rather than asserted: submitting an empty org drawing deletes 0 concepts and 0 states — all had other witnesses — and retires only the 6 edges that no other drawing had. Reading all sixteen drawings and writing them back unchanged leaves 24 concepts / 25 states / 20 causal / 50 structural exactly as they were.

6 · The loaders

ScriptBuilds
seed.pyThe n=6 reference, from literals in the file itself.
load_composite.pycomposite26, from tools/eip-schema-cld.json.
load_aspects.pyaspects16, from the sixteen files in tools/eip-aspects-variabilized/.

All three wipe and rebuild, so the migration is always just re-running the loader. Nothing needs converting in place, because nothing originates in Neo4j. Constraints are created in code with IF NOT EXISTS, so there is no schema step to remember.

The wipes are label-scoped, not global. If you add a new node label, it must be named in all three wipe clauses or it survives every rebuild and silently accumulates — with counts that still look plausible. This is the single easiest way to corrupt the substrate, and it produces no error.

families.js is read by graph-composer.html in a browser and by all three Python loaders. It is the highest-leverage file in the toolset: a syntax error there breaks the Composer and the substrate at once.

opmType is declared, never derived. Eighteen of thirty concepts are classified; twelve are deliberately left blank, because "we decided this is a thing" and "nobody has said yet" are different facts and the second one should look like itself.

8 · Things that are never correct

Editing :Family or :LinkFamily in the Neo4j Browser. They are generated copies of families.js and edge-families.js. An edit survives until the next loader run and then vanishes, with no error and no trace. Vocabulary changes rarely and deliberately, so it belongs under version control where it gets history, diff, review and rollback — none of which Neo4j gives a node edited in place.

Also never correct:

  • Storing anything derivable. Gold, family colour, a family's weight. Two answers to one question is the failure this exists to end.
  • Storing coordinates. Layout belongs to a drawing.
  • Inferring what a source is. Declare it on the :Aspect registry.
  • Assigning a relation family to make a count tidy. Seventeen edges have none; they are counted and left alone.
  • Normalising an author's verb. The edge merge key includes the raw label. constitute and constitutes drifting apart is fixed by suggesting existing spellings while typing, not by rewriting what somebody wrote.

9 · Troubleshooting

SymptomCause and fix
cannot reach from db.py --checkNeo4j Desktop is not running the RCN SCHEMA server. Start it by hand.
A projection 404s with no projection '…'An older api.py is holding port 8768 and never loaded the route. lsof -ti tcp:8768 | xargs kill -9, then restart. pkill -f api.py does not always match it.
A tool loads cleanly and draws nothingAlmost always missing x/y. A node with no coordinates gets a NaN centre, paints nothing, and still reports a successful load.
A concept appears twice and never goes goldThe merge key did not normalise — Active Goal versus ActiveGoal. Fix the spelling in the drawing; canon() handles spaces.
Counts grow on every loader runA node label is missing from the wipe clauses. See §6.
A saved edit reverts on the next loadOnly the database was written, not the file. Both stores must move together.
A drawing opens with fewer nodes than its fileShould no longer happen — subgraph() and the file writer are one code path. If it does, that path has been split again.
Family colours are greyThe :Family nodes lost their palette. Re-run the loaders, which read families.js as the one source.
