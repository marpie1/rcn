User Manual

Step-by-step guide to the nine-step Vester Influence Analysis pipeline, from system description through simulation.

Overview

The Vester Influence Analysis suite implements Frederic Vester's nine-step Sensitivity Model across two interoperable tools:

  • Vester app (vester.relocalizecreativity.net) — Steps 1–6: the analytical and structural preparation steps. All variable definitions, matrix scores, and role classifications live here.
  • RCN Graph Tool — SFD mode (graph-tool-v22.html) — Steps 7–9: the structural diagram, lookup table curves, and simulation engine.

Variables defined in the Vester app are the shared objects across both tools. The JSON export from the Vester app is the handoff format between them.

Starting a new project

  1. Open the Vester app and type a model name and purpose in the top bar.
  2. Work through Steps 1–6 in order using the tabs in the navigation bar.
  3. Use ↓ Save to download a JSON file at any point. Use ↑ Load to resume from a saved file.
  4. When Steps 1–4 are complete, open graph-tool-v22.html and switch to SFD mode for Steps 7–9.
Save frequently. The Vester app autosaves to browser localStorage, but that can be cleared. Export a JSON file at the end of every working session.

Data flow

The Vester app saves all state (variables, criteria, matrix scores, notes) in a single JSON file. The structure is human-readable and version-controllable. Future versions will include a "Send to SFD" button that pushes variables directly into the graph tool as SFD nodes, maintaining shared IDs across both tools.

Step 1

System Description Built

Tab: "0 System Description" — Tool: Vester app

Frame the problem before touching any variables. A clear system description keeps the group anchored throughout the matrix scoring and prevents scope creep.

What to enter

FieldWhereWhat to write
Model nameTop barShort identifying name, e.g. "Superior AZ Neighborhood System"
Model purposeTop barThe problem or question being addressed
System descriptionMain text areaFree text: what is inside the system? What is outside? Who is affected? What timeframe? What counts as a change worth modeling?
NotesNotes panelWorking notes, facilitator comments, unresolved boundary questions

Tips

  • Define the boundary explicitly. A variable that is "outside" the system is still a driver — it becomes a cloud in the SFD.
  • State the problem as a question, not a goal: "Why does X stay stuck despite interventions?" works better than "How do we improve X?"
  • This step often takes longer in a group than expected. Budget 30–60 minutes.
Step 2

Variable Set Built

Tab: "1 Variable Set" — Tool: Vester app

Collect the key variables of the system — the quantities, states, or conditions that change over time and influence each other. Aim for 20–30 variables. Fewer than 15 produces a thin model; more than 30 makes the impact matrix cognitively unmanageable.

Adding and editing variables

  • Click Add Variable to create a new entry.
  • Each variable has: name, description, and a 0–30 scale with min/max labels, intermediate anchor points, and an optional optimum.
  • Variables are numbered automatically. The number appears in matrix headers.

Designing the scale

The 0–30 scale is not arbitrary — it should be anchored to observable states at the extremes and at meaningful intermediate points. Examples:

  • 0 = "No employment, most adults idle" — 30 = "Full employment, labor shortage"
  • 0 = "No green space, fully paved" — 30 = "Extensive parks and gardens throughout"

The optimum is the value that is best for the system — not always the maximum. Mark it to enable color evaluation later.

Tips

  • Variable names should be short — 2–4 words. They appear in matrix column headers.
  • Avoid yes/no variables. The scale should capture a meaningful continuum.
  • If a variable could be split into two distinct things, split it. Clarity matters more than brevity at this stage.
A warning appears when the variable count exceeds 30. The impact matrix will have more than 900 non-diagonal cells, which is cognitively demanding for a group to complete in a single session.
Step 3

System Criteria Built

Tab: "2 System Criteria" — Tool: Vester app

Assess each variable against 24 criteria organized in 5 groups. This step reveals the character of each variable — what domains it belongs to, how it moves, and what kind of system relationship it has. The results inform role classification in Step 5.

The 24 criteria

GroupCriteria
Spheres of Life (7)Economy, Population, Space utilization, Human ecology, Natural balance, Infrastructure, Rules and laws
Physical Category (3)Matter, Energy, Information
Dynamical Category (4)Flow quantity, Structural quantity, Temporal dynamics, Spatial dynamics
System Relationship (4)Opens system through input, Opens system through output, Can be influenced from inside, Can be influenced from outside
Corporate Performance Criteria (6)Market Position, Innovation Performance, Productivities, Attractiveness to Right People, Liquidity and Cash Flow, Profitability

Scoring

  • Select a variable on the left panel, then assess each criterion for that variable.
  • Three states: ● Applies, ○ Partially applies, ✕ Does not apply. Unscored = not yet assessed.
  • A completion counter shows how many criteria have been assessed for the selected variable.

Customizing criteria

Criterion labels and definitions are editable. If "Corporate Performance Criteria" doesn't fit your context (e.g. you're modeling a neighborhood, not a company), rename the group and redefine each criterion to fit. Changes are saved in the JSON.

For neighborhood and community work, the CPC group is often adapted to reflect community health indicators, social cohesion, or civic capacity rather than corporate metrics.
Step 4

Cross-Impact Matrix Built

Tab: "3 Impact Matrix" — Tool: Vester app

The heart of the method. Score how strongly each variable influences every other. This is where shared understanding of the system's structure emerges — often for the first time in a group.

Reading the matrix

  • Rows = source variable (the one doing the influencing)
  • Columns = target variable (the one being influenced)
  • Each cell answers: "How strongly does Row variable influence Column variable?"
  • Diagonal = disabled (grayed out). A variable cannot influence itself.

Scoring scale

ScoreColorMeaning
0White/grayNo direct influence
1Light blueWeak influence
2Medium blueMedium influence
3Dark blueStrong direct influence

Click any cell to cycle through 0→1→2→3→0. The score updates immediately and is autosaved to localStorage.

Active Sum and Passive Sum

  • Active Sum (AS) — shown in the right column. Sum of all scores in that row. How much this variable drives others.
  • Passive Sum (PS) — shown in the bottom row. Sum of all scores in that column. How much this variable is driven by others.

These two numbers per variable feed directly into Step 5 (System Roles).

Group scoring approach

The matrix is most valuable when scored by the group together, not by individuals separately. A productive sequence:

  1. Project the matrix on a screen everyone can see.
  2. Work row by row: "Does variable X influence variable Y?" Go around the table.
  3. Score disagreements by discussion, not averaging. The debate itself surfaces hidden assumptions.
  4. Score quickly on first pass — aim for 2–3 hours for a 20-variable matrix. Refine in a second pass.
Score direct influence only — not indirect effects through other variables. If A influences B which influences C, score A→B and B→C, not A→C (unless A also directly influences C).
Step 5

System Roles Built

Tab: "4 System Roles" — Tool: Vester app

This step is built and working in the Vester app.

Once the matrix is complete, each variable's Active Sum and Passive Sum place it in one of four systemic roles:

Active
High AS, Low PS
Strong drivers with few feedbacks. Good intervention levers — but effects may be unpredictable downstream. Changing these creates momentum.
Critical / Reactive
High AS, High PS
Highly influential and highly influenced. These are the most dangerous variables to disturb — they amplify disturbances through the system. Handle with care.
Buffering
Low AS, Low PS
Stable dampers. Weakly connected to everything. They absorb shocks and reduce oscillation. Preserve these — disrupting them removes system stability.
Passive / Indicator
Low AS, High PS
Result variables. They reflect the state of the system but don't drive it. Good choices for measurement and outcome tracking.
← Low Passive Sum            High Passive Sum →

The quadrant plots each variable by its AS and PS, with Q-isolines (hyperbolas of constant AS × PS) showing systemic relevance. A sorted variable list below shows each variable's role classification and Q value. Variables can be selected to highlight them on the chart.

Step 6

Partial Scenario Built

Tab: "5 Partial Scenario" — Tool: Vester app

The Partial Scenario tool implements the full Vester simulation pipeline in three phases: variable selection, transfer curve construction, and simulation with trajectory tracking.

Phase 1 — Variable Selection

Choose which variables to include in the scenario (typically 8–15). Each variable is shown with its role badge (Active/Critical/Passive/Buffering) and Active Sum score. The tool shows scored relationships in the selected subset and warns if no edges exist between selected variables. Name the scenario before proceeding.

Phase 2 — Transfer Curves

For each scored relationship in the selected set, draw a transfer curve — a graphical function that maps the source variable's state (Y axis, 0–30) to its effect per simulation step on the target variable (X axis, −5 to +5). Scale anchor labels from Step 2 appear on the Y axis.

  • Click an arrow in the network diagram to open its curve editor
  • Click on the canvas to add a control point; drag to move it; double-click to remove
  • Dashed extensions above/below the outermost points extrapolate the curve to the boundaries
  • Red shading = dampening effect; green shading = amplifying effect
  • Add a text description per curve to record group reasoning
  • Progress counter shows how many curves have been defined

Phase 3 — Simulation

Click Run simulation to initialize all variables at their Step 2 optimum values (or 15 if no optimum set). Then:

  • Step — advance one round: each variable's effect is computed from its transfer curve at the current source state, accumulated across all relationships, and applied to the target
  • Reset — return all variables to initial states
  • Sliders — manually intervene on any variable between steps to test perturbations
  • Trajectory chart — time-series lines for all selected variables across rounds
Not yet implemented: multi-scenario side-by-side comparison, export of simulation results, and biocybernetic evaluation against Vester's 8 basic rules.
Step 7

Stock & Flow Diagram Built

Tool: RCN Graph Tool — graph-tool-v22.html — SFD mode

The SFD translates the system's influence structure into a formal runnable model: stocks that accumulate, flows that change them, auxiliaries that modify flow rates, and clouds that mark system boundaries.

Entering SFD mode

Open graph-tool-v22.html. In the right panel, click the SFD button in the mode selector. The SFD palette replaces the standard node palette.

Element types

ElementShapeMeaningFields
StockThick-bordered rectangle (blue fill)Accumulates a quantity over timeInitial Value, Equation
Flow / ValveCircle with × (white)Controls the rate of change into or out of a stockEquation
AuxiliaryEllipse (yellow fill)Helper variable, constant, or parameter that modifies a flow rateEquation
CloudBumpy ellipse (gray)Infinite source or sink — the system boundaryNone

Edge types

EdgeAppearanceMeaning
PipeThick dark line (5px, round caps)The flow path between stock/cloud and valve
ConnectorThin curved arrowInfluence: auxiliary → valve or auxiliary → stock

Drawing flows

  • Select +Edge in the SFD palette, then click a Stock and click another Stock or Cloud. A valve is automatically inserted at the midpoint with two pipe edges connecting them.
  • To draw a pipe segment manually (valve already exists), click +Edge, then click the valve and click the stock/cloud.
  • Select +Connector to draw an influence arrow from an Auxiliary to a Valve or Stock.

Equations (placeholder)

The Equation field in the Properties panel is currently a free-text field. Enter a description or a placeholder expression. In Step 8, this field will be replaced by a lookup table curve editor.

XMILE export

The SFD→XMILE button (visible only in SFD mode) exports the diagram in XMILE format — the standard interchange format for system dynamics models. The file can be opened in:

  • Vensim — import via File → Import XMILE
  • Insightmaker — use File → Import → XMILE

XMILE export is the current bridge for running simulations while the built-in simulation engine is under development.

Step 8

Lookup Table Curves Planned

Tool: RCN Graph Tool — graph-tool-v22.html — SFD mode

This step is planned and not yet built. The Equation text field in Properties is the placeholder hook.

Vester's "biokybernetik" approach replaces mathematical equations with graphical functions — curves that map an input variable (on the 0–30 scale) to an output effect (normalized). These curves are constructed by the group, not computed — they capture qualitative expert knowledge about how variables actually relate.

When built, each Flow or Auxiliary will have a curve editor that:

  • Shows a canvas with input (x) on the horizontal axis and output effect (y) on the vertical axis
  • Allows the group to drag the curve into the shape they believe is correct
  • Records who drew the curve and when
  • Shows uncertainty bands where group members disagreed

This is the key piece that separates Vester's method from conventional system dynamics — expertise lives in the curve shape, not in a formula.

Step 9

Simulation Planned

Tool: RCN Graph Tool — graph-tool-v22.html — SFD mode

This step is planned and not yet built. XMILE export (Step 7) is the current bridge to external simulators.

The simulation engine will run Euler integration reading from the lookup table curves defined in Step 8. For each time step:

  1. Each auxiliary computes its output by reading its lookup curve at the current value of its input variable
  2. Each flow (valve) computes its rate from the auxiliaries that influence it
  3. Each stock is updated: Stock(t+dt) = Stock(t) + (inflows − outflows) × dt
  4. Results are recorded and plotted as time series

When built, what-if runs will allow testing different initial conditions and scenario states from Step 6, with results evaluated against Vester's 8 biocybernetic basic rules as a diagnostic layer.

Workflow tips

Session planning

Step 7 (SFD first draft)1–2 hoursFacilitator + 1–2 subject matter experts

Save and backup

  • Export a JSON file at the end of every session using ↓ Save.
  • The filename includes the model name. Keep dated copies: superior-az-2026-07-17.json.
  • Browser localStorage can be lost if the browser data is cleared. The JSON file is the authoritative save.

Variable naming

  • Keep names to 2–4 words. They appear in rotated column headers in the matrix — short names stay legible.
  • Use noun phrases, not questions or actions: "Employment Rate" not "Are people employed?"
  • Avoid abbreviations in Step 2 — use the description field for expansions.

The matrix as conversation

The most common mistake is treating the matrix as a data-entry task. It is a structured conversation. Every cell where the group disagrees is a place where assumptions differ — surfacing that disagreement is the point. A matrix scored by one person in an afternoon is less valuable than a matrix scored by a group over two sessions.
