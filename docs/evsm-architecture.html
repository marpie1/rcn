What you need to do to move to a server

Note: The Aggregator now calls the Anthropic API directly from the browser using the user's own API key (stored in localStorage). A proxy server is no longer required for Claude. The steps below describe how to host the static files on a server — the Claude API call will continue to work from the browser without any proxy.
  1. Pick a server. Any Linux VPS works (Linode, DigitalOcean, AWS EC2). You need Python 3 and a static file server. No database required for eVSM.
  2. Copy the files. Upload tools/evsm-svg-v3.html, tools/evsm-aggregator.html, tools/evsm-report.html, and tools/evsm_excel_tool.html to the server. data/evsm-proxy.py is optional — it is no longer needed for Claude calls since users supply their own API key in the browser.
  3. Serve the static files. Use any static file server (Python's http.server, nginx, Apache). No server-side API key configuration is required.
  4. Set up a process manager (optional). Use systemd to keep your file server running. Create a /etc/systemd/system/evsm-tools.service unit file.
  5. Open the firewall port for your static server (or 80/443 if behind nginx). eVSM has no other server-side dependencies.
  6. Optional: put nginx in front. Nginx on port 443 (HTTPS) gives you TLS and a clean URL.
  7. Optional proxy for shared key. If you want to provide a shared Anthropic API key rather than requiring each user to supply their own, run evsm-proxy.py and set ANTHROPIC_API_KEY in its environment. Users would then need the proxy's URL configured in the aggregator.

What does NOT need to change

  1. The HTML tools themselves are pure browser code — no server-side rewrites needed.
  2. JSON file exchange still happens via download/upload — no shared filesystem needed between respondents and facilitator.
  3. The print flow uses blob URLs (not sessionStorage) — works for local files and served files alike, as long as evsm-svg-v3 and evsm-report are in the same folder (local) or served from the same origin (server).
  4. Claude API calls go directly from the browser to Anthropic using the user's own key — no proxy configuration needed.
  5. Firebase, Neo4j, PostGIS — none of these are used by eVSM. Leave them on this machine.
