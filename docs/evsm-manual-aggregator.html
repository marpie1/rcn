Aggregator

Load multiple respondent files, view aggregated assessments, filter by subgroups, and use Claude AI to synthesize narrative insights.

evsm-aggregator.html

Overview

The Aggregator is the analysis tool. After collecting response JSON files from all respondents, the facilitator or analyst loads them here to see the combined picture. The tool shows how many respondents assessed each sphere and relationship, what the distribution of opinions is, and what people wrote in their evidence and suggestion fields.

The key analytical features are:

  • Aggregated diagram — spheres and edges colored by the distribution of assessments across all respondents
  • World set filtering — narrow the view to a subgroup defined by world categories
  • Compare mode — view two subgroups side by side
  • Claude synthesis — AI-generated narrative summaries of what a group of respondents said about a specific sphere or relationship
  • Synthesize All — run Claude sequentially across every sphere and edge with at least one assessment; syntheses are cached in memory
  • Full Report — generate a complete standalone HTML report containing the diagram, all sphere and edge detail, evidence, suggestions, and syntheses
  • Session export / restore — save the entire session (responses, labels, syntheses) as a JSON bundle; drop it back in to restore the session without re-running Claude

Loading Responses

  1. Open the Aggregator in your browser.
  2. Drag one or more response JSON files onto the drop zone in the left panel, or click the drop zone to browse for files.
  3. Each loaded respondent appears in a list below the drop zone, showing their name (or ID) and world tags.
  4. The diagram updates automatically.

You can load files in batches — drag another set of files at any time and they are added to the existing set. Duplicate responses (same respondent ID or same filename) are ignored silently.

To remove a respondent, click the × button beside their name in the list.

Session bundles: dropping an evsm-session-*.json file onto the drop zone restores a previously saved session — all respondents reappear, labels load, world set filters restore, and cached syntheses are available immediately. See "Saving and Restoring Sessions" below.
Master config tip: if you want authoritative sphere labels (not derived from any respondent's potentially-modified config), drop a clean master config JSON onto the drop zone first, before any respondent files. It seeds the labels without adding any assessment counts.
Load as many or as few response files as you have. The Aggregator works with partial data — you do not need to wait for every respondent.

Reading the Diagram

The aggregated diagram uses visual encoding to communicate the distribution of assessments at a glance:

Spheres (nodes)

Each circle is filled with stacked color bands showing the proportional breakdown of responses. The bands run from bottom to top in the order: Stop (red), Caution (yellow), Go (green), Unsure (blue). A predominantly green sphere means most respondents rated it well; a predominantly red sphere signals a shared concern.

Relationships (edges)

Arrow width scales with the number of respondents who assessed that relationship. Arrow color shows the majority opinion:

Green — majority Agree Red — majority Disagree Grey — mixed or Unknown

Viewing Detail

Click any sphere or edge in the diagram to open the detail view in the right panel. This shows:

  • Description — the facilitator's description of this element
  • Stat bars — a horizontal breakdown showing the percentage and count of each status choice
  • Evidence — all respondents' evidence text, grouped by world categories
  • Suggestions — all respondents' suggestion text, grouped by world categories

The evidence and suggestions show who said what in terms of their world category memberships. Use the respondent identity features below to see individual contributions when needed.

Respondent Identity

Four features let you move from aggregate patterns down to individual respondents and back.

Show Names (⊙)

Click ⊙ Show Names in the header to reveal each respondent's name or ID alongside their evidence and suggestion quotes in the detail panel. Click again (⊙ Hide Names) to return to anonymous display. This setting persists across element selections until toggled off.

Per-respondent filter

In the respondent list (left panel), click any respondent's name to filter the detail panel to show only that person's quotes. The selected name is highlighted. Click the name again, or click × Clear respondent filter that appears at the top of the list, to return to the full view.

Compare individual vs aggregate (⇄)

Each respondent in the left panel has a ⇄ button. Clicking it immediately switches to Compare mode with that respondent as Set A and "All Respondents" as Set B. You can see at a glance where one person's assessments differ from the group consensus. The per-respondent filter (above) is also activated simultaneously, so the detail panel shows only that person's quotes.

Rich hover panel

Hover over any sphere or edge in the SVG diagram to see a floating panel listing every respondent who assessed that element, with a colored dot showing their status choice (green = Go, yellow = Caution, red = Stop, blue = Unsure). Two actions are available from the hover panel:

  • Click a respondent's name — activates the per-respondent filter for the detail panel (same as clicking the name in the left panel).
  • Click ⇄ beside a name — activates both the per-respondent filter and Compare mode for that individual vs all respondents.

The hover panel stays open while your mouse is over it, giving you time to click. It disappears when you move the mouse away from both the SVG element and the panel.

World Set Filtering

World categories are the demographic or role descriptors respondents selected when completing the survey. Use them to focus the aggregated view on a specific subgroup.

Filtering Set A

In the left panel, check any world categories under the Set A section. The diagram and detail view update to show only respondents who match that filter. The respondent count updates to reflect how many people match.

Two filter modes control how the matching works:

ModeBehaviorUse when…
ExclusiveRespondent must have ALL checked worldsYou want a tightly defined group (e.g., "longtime residents who are also renters")
InclusiveRespondent must have ANY checked worldYou want everyone in a broad category (e.g., "anyone who is under 30 OR new to the area")

Leave all world checkboxes unchecked to include all respondents (no filter applied).

Compare Mode

Compare mode lets you define two separate subgroups and view them side by side. This is the main tool for surfacing where different segments of the survey population see things differently.

  1. Click Compare Sets in the header.
  2. Two diagrams appear side by side. Set B filter controls appear below Set A in the left panel.
  3. Give each set a descriptive name using the name fields (defaults: "Set A" and "Set B").
  4. Configure the world filters for each set independently.
  5. Click any sphere or edge in either diagram to see detail for both sets.

In Compare mode, clicking an element opens a selector in the right panel with three options:

  • Set A only — show detail and synthesize for Set A respondents
  • Set B only — show detail and synthesize for Set B respondents
  • Compare Set A vs Set B — show both sets' stat bars side by side, and use Claude to write a comparative synthesis highlighting where the groups agree and differ

Claude Synthesis

The Synthesize button uses Claude AI to generate a narrative paragraph summarizing what a group of respondents said about the selected sphere or relationship. It draws on their evidence and suggestion text, not just the status counts.

Setting your API key

Look for the API key area in the right panel (below the Synthesize button). If no key is stored, it shows an input field. Paste your Anthropic API key (sk-ant-...) and press Enter or click Save. The key is stored in your browser's local storage — you only need to enter it once per browser.

The Aggregator calls the Anthropic API directly from the browser using your own API key. No proxy server is required. The model used is claude-sonnet-4-5.
Your API key is stored in your browser only. It is never sent to any server other than Anthropic's API directly. You are billed by Anthropic for each synthesis request at standard API rates.

Running a synthesis

  1. Select a sphere or edge in the diagram.
  2. Click ✦ Synthesize with Claude in the right panel.
  3. The response streams in real-time below the button.
  4. Click ✦ Re-synthesize to run it again (e.g., after adding more response files).

For comparative synthesis (Compare mode), select "Compare Set A vs Set B" from the selector, then click the synthesis button that appears. Claude will articulate where the two groups converge and where their perspectives diverge.

Any synthesis generated via the per-element Synthesize button is cached in memory and included in the session export (see below). Sessions can be saved and resumed without re-running Claude.

Synthesize All

Click ✦ Synthesize All (purple button in the header) to run Claude sequentially for every sphere and relationship that has at least one assessment. This is the fastest way to prepare a full set of narrative summaries before generating the Full Report.

A progress overlay appears showing which element is currently being synthesized and how many remain. A Cancel option is available — any syntheses completed before cancellation are kept. When all syntheses are complete, the tool offers to generate the Full Report immediately.

Full Report

Click ⎙ Full Report (blue button in the header) to generate a complete standalone HTML report in a new browser tab. The report contains:

  • Survey metadata header
  • The eVSM SVG diagram, colored by aggregate assessments
  • All 11 spheres — each with description, response count bars, evidence, suggestions, and synthesis (if available)
  • All assessed edges — same structure
  • A Print / Save PDF button

The Full Report works with partial syntheses — items that have not been synthesized still appear with their evidence and suggestions; they just have no synthesis block. Use Synthesize All first for a complete report.

Saving and Restoring Sessions

Click ⬇ Export Session (amber button in the header) to save the entire current session as a single JSON bundle. The file is named evsm-session-{timestamp}.json and contains:

  • All loaded respondent response files
  • Sphere labels and edge descriptions
  • World set configuration (Set A and Set B filters)
  • All Claude syntheses generated so far

To restore a session, drop an evsm-session-*.json bundle onto the Aggregator's drop zone. All respondents reappear, labels reload, world set filters restore, and cached syntheses are available immediately — without re-running Claude.

Print button

Click ⎙ Print (green button in the header) to print the current detail panel — whatever sphere or edge was last selected — using the browser's print dialog. All other panels are hidden during print. Use this for quick single-element printouts without generating the full report.
