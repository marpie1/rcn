# Models and Patterns

> The approach to modeling in ReLocalize Creativity is to reveal rich perspectives and possibilities (leverage points) in particular systems — NOT to create generalized models. Our generalizations will be published as Patterns. — [[Models for Seeing Systems]]

This is the cleanest statement of the whole architecture, and it draws a hard line.

A model is a particular. This neighbourhood, this hospital's pricing, this coop's finances — drawn to reveal leverage in that system, and not expected to travel.

A pattern is the generalization, abstracted from particulars and published so that someone else can use it.

## What it settles

The example files in the repo — the causal loop diagrams, the Rent Band Analysis pricing graph, the POMR set — are models. The method pages are patterns. An example is not decoration on a method page; it is the particular the general was abstracted from, and the link between them should be explicit in both directions.
