Teaching Graph — User Manual

How to build the teaching graph from your SODOTO (See One, Do One, Teach One) badges and ask it questions. Everything runs on the Desktop Substrate; you need a terminal and, optionally, the Neo4j Browser.

Before you start

The graph lives on the Desktop, not on WikiCafe. You need:

  • Neo4j running — the DBMS started in Neo4j Desktop (5.26.4). Reachable at http://localhost:7474.
  • Credentials — ~/rcn/.env.neo4j (gitignored) with NEO4J_HTTP, NEO4J_USER, NEO4J_PASSWORD, NEO4J_DATABASE. Already set up on Marc's machine.
  • Badges to read — the FedWiki portfolio pages. By default the projector reads ~/.wiki/localhost/pages; point it elsewhere with --pages.

No Python packages to install — the projector and db.py talk to Neo4j over plain HTTP using only the standard library.

Build the graph

  1. See what would project (no database needed). A dry run lists every badge it found and would load — a good first sanity check. 
    python3 substrate/sodoto_projector.py --check
  2. Project into Neo4j. Reads the badges and upserts the graph. Idempotent — safe to run over and over. 
    python3 substrate/sodoto_projector.py
  3. Project and see a summary. Adds counts and a "most active mentors" readout after loading. 
    python3 substrate/sodoto_projector.py --summary
Idempotent. Every node and edge is MERGEd on a stable key (a credential on its contractId). Re-running after new badges are issued adds the new ones and leaves the rest exactly as they were — no duplicates.

Two ways to query

Once the graph is built, ask it anything in Cypher:

From the terminal

python3 substrate/db.py -q "MATCH (c:Credential) RETURN count(c)"

In the Neo4j Browser

Open http://localhost:7474, sign in, and paste a query. The Browser draws the graph visually — the nicest way to explore lineages and click around the network.

The schema

Nodes and the main relationships (NDC = Neighborhood Development Center). The full relationship set is in the table below.

Nodes

NodeKeyProperties
Persondidname — a mentor, learner, and/or student depending on the edge

Query library

Copy any of these into db.py -q "…" or the Neo4j Browser.

Teaching lineage — trace who taught whom, to any depth

MATCH path=(root:Person)-[:TAUGHT*]->(leaf:Person)
WHERE NOT ()-[:TAUGHT]->(root)
RETURN [n IN nodes(path) | n.name] AS chain, length(path) AS hops
ORDER BY hops DESC

Every teaching chain from its origin, longest first (e.g. [Kerry, Marc, Noah]).

Most active mentors

MATCH (m:Person)-[:TAUGHT]->(l:Person)
RETURN m.name AS mentor, count(DISTINCT l) AS learners
ORDER BY learners DESC

Who has grown the most distinct practitioners.

Everything one person holds

MATCH (p:Person {name:"Marc Pierson"})-[:HOLDS]->(c:Credential)-[:CERTIFIES]->(s:Skill)
RETURN s.name AS skill, c.version AS version, c.partial AS partial
ORDER BY skill

A person's full credential set, with version and whether it's partial.

Who taught a person — and who they taught

MATCH (teacher:Person)-[:TAUGHT]->(:Person {name:"Marc Pierson"})
RETURN DISTINCT teacher.name;
// and the other direction:
MATCH (:Person {name:"Marc Pierson"})-[:TAUGHT]->(student:Person)
RETURN DISTINCT student.name

A person's mentors and the people they have taught.

Who can do a skill

MATCH (p:Person)-[:HOLDS]->(c:Credential)-[:CERTIFIES]->(:Skill {name:"Causal Loop Diagramming"})
RETURN p.name AS holder, c.version AS version, c.partial AS partial
ORDER BY holder

Everyone credentialed in a given skill (with how complete).

Where a skill entered the network (roots of the teaching tree)

MATCH (r:Person)-[:TAUGHT]->()
WHERE NOT ()-[:TAUGHT]->(r)
RETURN DISTINCT r.name AS origin

The people no one taught — where teaching chains begin.

Provenance of a credential

MATCH (o:Organization)-[:ISSUED]->(c:Credential {contractId:"sodoto-cld-rcn-2025-0001"})
MATCH (c)-[:HAS_GATE]->(g:GateAttempt)
RETURN o.name AS issuer, c.version, collect(g.gate + " (" + g.completedAt + ")") AS gates

Who issued a credential and which gates it passed, with dates.

Learner-attested (v0.4) credentials

MATCH (p:Person)-[:HOLDS]->(c:Credential)
WHERE c.learnerAttested
RETURN p.name AS holder, c.skill AS skill, c.version

Credentials the learner cryptographically signed (the v0.4 mutually-attested ones).

Gates that took more than one try

MATCH (c:Credential)-[:HAS_GATE]->(g:GateAttempt)
WHERE g.attempts > 1
RETURN c.holderDid AS learner, c.skill, g.gate, g.attempts
ORDER BY g.attempts DESC

Where a learner needed multiple attempts — evidence of rigor, not failure.

Credentials per issuing NDC

MATCH (o:Organization)-[:ISSUED]->(c:Credential)
RETURN o.name AS ndc, count(c) AS credentials
ORDER BY credentials DESC

How many credentials each cooperative has issued.

Refreshing & options

  • Refresh after new badges — just run the projector again. Idempotent; new credentials are added, existing ones untouched.
  • A different wiki — --pages /path/to/other/pages (e.g. a copy of the WikiCafe portfolios synced to the Desktop), or set WIKI_PAGES.
  • Dry run anytime — --check never touches Neo4j; use it to preview what a folder holds.

Troubleshooting

SymptomFix
"cannot reach http://localhost:7474"Start the DBMS in Neo4j Desktop. Confirm with python3 substrate/db.py --check.
"missing ~/rcn/.env.neo4j"Create it with your Neo4j host/user/password/database (see substrate/README.md). It is gitignored — never commit it.
"pages folder not found"Point --pages at the FedWiki pages directory that holds the portfolios.
The same person shows up as two nodesThat person has different Decentralized Identifiers (DIDs) across badges. The graph correctly keys people by DID — the fix is clean data: one self-custodied DID per person (see the SODOTO reference). Not a projector bug.
A count looks off vs. the badge countTwo badge items can share a contractId (the same credential on two pages); they correctly collapse to one Credential.
The badges are the truth. If the graph and a portfolio ever disagree, trust the badge and rebuild the graph — it is only ever a projection.
