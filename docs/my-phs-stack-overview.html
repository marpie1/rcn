My Personal Health Supporter — Stack Overview

Neighborhoods are the actual health system. My Personal Health Supporter is a suite of six open-source tools — a person-owned clinical record, an active problem view shaped by positive affect, an AI-assisted option explorer, a support network completeness view, and a portable skill credentialing system — built for health partners, cooperative organizers, and the communities they work in. No tool is for sale. The cooperative is the sustainability model.

My Shared Care Plan is the source of truth for both My Health Picture and My Health Choices. Health Choices writes structured shared-decision records back to SCP via the record API. PANAS scores are stored raw in SCP and version-tracked; the band mapping is a named crosswalk table separate from stored scores. My Support Network reads care team data from SCP. SODOTO credentials are independent — verifiable digital badges not stored in SCP and not owned by any institution.

My Shared Care Plan

My Shared Care Plan is the clinical ground truth that every other tool draws from. It is implemented as 13 typed FedWiki plugins: scp-medication, scp-vital, scp-symptom, scp-visit, scp-lab, scp-about, scp-provider, scp-diagnosis, scp-reaction, scp-history, scp-next-step, scp-directive, scp-access. Each plugin type enforces a schema while remaining a first-class FedWiki page item — editable, forkable, federated.

The record is person-owned and decentralized. No institution holds it. The commit+fold pattern is used on every save: the item is updated in place and the previous version folded into history. Every item populates item.text on save so FedWiki's full-text search indexes all clinical content.

  • Pilot: per-patient FedWiki sites (rosa-delgado.localhost, alex-rivera.localhost) — isolated instances seeded from canonical templates in ~/rcn/scp/pages/
  • Target production: WikiCafé (ndcgroup.relocalizecreativity.net)
  • FedWiki plugins follow the naming convention wiki-plugin-scp-*; published to npm; symlinked for localhost dev

My Health Picture

My Health Picture is the active problem list layer over the Shared Care Plan. It structures every active problem using SOAP — Subjective, Objective, Assessment, Plan — and attaches three flags per problem: certainty (Confirmed / Probable / Possible / Unconfirmed / Not Pursuing), urgency (attention codes 1–5: Act Now through Routine), and the next best question — the single most important missing evidence for that problem.

The PANAS PA-10 activation score (see below) shapes which problems are shown. Bands 1–2 filter to urgent and critical problems only; bands 3–4 open the full list. "Show full frame" always overrides. The view is served by coupler-proxy.py on port 8766, which also handles FedWiki write-back.

Physician package

When escalation is needed, My Health Picture generates a structured package: the specific problem at its level of certainty, gathered evidence, health partner observations, and one clear question for the physician. The physician's written response goes back into the Shared Care Plan — timestamped, attributed, indexed.

PANAS PA-10

The Positive and Negative Affect Schedule positive-affect subscale is a 10-item score taken at every visit. The person rates 10 words for the past week on a 1–5 scale: active, alert, attentive, determined, enthusiastic, excited, inspired, interested, proud, strong. Total score runs 10–50.

ScoreBandEffect on Health Picture view
10–24Learning the basicsFilter to urgency codes 1–2 only
25–31Building awarenessFilter to urgency codes 1–2 only
32–38Taking actionFull problem list shown
39–50Staying the courseFull problem list shown

Scores are stored raw in SCP. The band is derived at runtime from a named crosswalk table — updating the table never touches stored scores. The measurable hypothesis: activation scores should rise over time as a person engages with the tools. The trajectory is auditable because every score is version-tracked.

My Health Choices

My Health Choices is an AI-assisted conversation about a specific active problem. It opens pre-loaded with the person's full SCP context, passed in from My Health Picture for a specific problem. The health partner and person explore options together in plain language. When quantified evidence is available, the tool renders an Option Box: a 1,000-dot SVG on a 40×25 grid — teal dots are people helped, red are people harmed, grey are unaffected. This makes NNT and NNH visible at a glance rather than as fractions.

Drug safety pipeline

Behind the AI conversation, the tool pulls openFDA drug labels, FAERS adverse event counts, and MedlinePlus plain-language terms. Three built fact boxes are in the library: AF anticoagulation, statin primary prevention, and hypertension medication vs. lifestyle. The keyword match system detects when an active problem aligns with a library entry and surfaces the "My Health Choices ↗" button directly in My Health Picture.

  • "Document this choice" writes a structured shared-decision record back to SCP via POST /api/record-entry
  • Served at port 8770; source directory: scp-optionbox/

My Support Network

My Support Network displays a person's care team against a maximal list of 27 roles across five categories: Medical, Therapy and Rehab, Community and Navigation, Informal Support, and Practical Support. The design principle is that absence is as visible as presence — unfilled roles appear as ghost nodes rather than being omitted.

  • Completeness ring: SVG circle showing how many of 27 roles are filled
  • Network graph: patient at center, current members in inner ring, empty categories as ghost nodes in outer ring
  • Many health problems are support problems, not clinical ones. This view makes that visible so the health partner can act on it.

Source: tools/my-support-network.html

SODOTO

See One, Do One, Teach One is the classic medical apprenticeship model formalized as a digital credentialing system. Three levels: Observer (watched a skilled partner complete a task) → Practitioner (completed it under witnessed conditions) → Teacher (guided a peer to their Practitioner credential). Teacher credential unlocks a higher pay tier. The network teaches itself — no training department required.

  • Credentials are verifiable digital badges: portable, not owned by any institution
  • In-browser Web Crypto verification — signing is the user's responsibility in the browser, never programmatic
  • Badge upsert pattern: issuer writes to FedWiki portfolio page; Verify button checks signature in-browser
  • Infrastructure: sodoto-issuer.html + sofi-proxy.py + FedWiki portfolio pages + sodoto-badge plugin
