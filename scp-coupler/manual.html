1. Starting the Tool

The coupler runs locally. You need a terminal and Python 3 on your machine. The AI model is reached through a local proxy — no data leaves your machine except through that proxy.

Open a terminal and run:

python3 coupler-proxy.py

When you see a line like Serving on http://localhost:8766, open your browser and go to:

http://localhost:8766

Leave the terminal window open while you work. The proxy must stay running. If the browser shows a connection error, check that the terminal is still active and try again.

The proxy process can be stopped at any time with Ctrl+C in the terminal. Your data is already saved — stopping the proxy does not lose anything.

2. Adding a Person and Problems

The main screen shows your list of people. Click New Person to add someone. Enter a name or identifier — the tool does not require a medical record number or any formal ID.

Once inside a person's record, the left panel shows their problem list. Click Add Problem and type a short problem title: for example, "Uncontrolled hypertension" or "New-onset fatigue." Problems can be anything the person considers worth tracking — a diagnosed condition, a symptom, a concern.

Keep problem titles short and specific. "Chest pain on exertion" is more useful than "Pain." The AI uses the title to build the frame, so clarity here improves everything downstream.

You can add as many problems as needed. Each one gets its own coupler frame. Click a problem in the list to open it.

3. Generating a Frame

When you open a problem that has no frame yet, you will see a Generate Frame button. Click it.

The AI builds a complete set of findings worth gathering for this problem — Subjective questions, Objective measurements, Assessment candidates, and Plan considerations. This takes 10–30 seconds depending on connection speed. A spinner shows while it works.

What the AI does during this step:

  • Reads the problem title and any existing record entries for this person
  • Produces a structured list of findings organized in SOAP order
  • Generates an initial ranked list of diagnostic candidates with probability estimates
  • Assigns an Attention Code to each candidate based on severity and probability

When the spinner clears, the full frame appears. Every slot that exists in the frame is visible — filled, partial, or absent.

The generated frame is a starting point. You can add, edit, or remove any slot. The AI's judgment about what findings matter is based on general clinical knowledge — the care team decides what applies to this specific person.

4. Reading the SOAP View

The frame is organized into four sections: Subjective, Objective, Assessment, and Plan. Each section contains rows — one per finding. Every row shows a status dot on the left.

Filled — a record entry exists for this finding
Partial — some information exists but the finding is incomplete
Absent — nothing has been recorded for this finding yet

Absent slots are the whole point. A gray dot on a finding is not a failure — it is information. It tells the care team, the physician, and the person themselves: this is something we haven't looked at yet for this problem.

Entering a Record Entry

Click any finding row to expand it. You will see the current record entries for that finding (if any) and a text field to add a new entry. Type what you know — a date, a measurement, a description, a direct quote from the person — and press Save Entry. The dot updates immediately.

Navigating Sections

Use the section tabs (S / O / A / P) at the top of the frame to jump between sections, or scroll through all four. The count of absent slots in each section is shown next to the tab label so you can see at a glance where the biggest gaps are.

5. Re-Match: Updating the Picture

Re-Match is the core update cycle. After you have added new record entries — one finding, several findings, or a whole visit's worth — click Re-Match in the Assessment header.

Re-Match does two things:

  1. Re-evaluates slot status. Every finding row is re-checked against the current record. Dots update from absent to partial or filled as appropriate.
  2. Re-estimates probabilities. The AI re-reads all current record entries and produces new probability estimates for every diagnostic candidate. The old estimates are preserved — a new row is appended to each candidate's probability history. You can see how the picture has shifted over time.

Think of Re-Match as: "Update everything with what we now know." You should run it at the end of each visit or whenever a significant new finding has been entered.

Probability history rows are never deleted or overwritten. If a candidate was 35% likely at the first visit and is 60% likely now, both numbers stay in the record. This is an intentional design choice — the trajectory of evidence matters as much as the current estimate.

6. Reading Assessment Candidates

The Assessment section shows a ranked list of diagnostic candidates. Each candidate displays:

  • Name — the diagnostic label
  • Attention Code — a number 1–5 (see table below)
  • Probability bar — a visual bar proportional to the current estimate, with the percentage shown
  • Severity class — the clinical weight of this diagnosis if confirmed (I = most severe)
  • Supported by — findings in the record that raise this candidate's probability
  • Refuted by — findings in the record that lower this candidate's probability
  • Probability history — a row for each Re-Match run, showing the estimate at that point in time

Click any candidate card to expand the full evidence detail.

Attention Codes

Code Meaning What it implies
1 Act Now High severity, possibility cannot be ignored regardless of probability rank. Needs immediate clinical attention.
2 Urgent High severity with meaningful probability. Elevate to clinical review within this visit or same day.
3 Watch Moderate severity or moderate probability. Keep active, monitor, close gaps in the next visit.
4 Follow Lower severity or lower probability. Worth tracking but not time-sensitive.
5 Let It Rest Low severity and low probability. On the list for completeness; no action indicated now.

The code is determined by a matrix that crosses severity class (I–IV) against probability band (A–D). A severe diagnosis at low probability still earns a high attention code. A mild diagnosis at high probability earns a low one. This ensures that rare but serious possibilities stay visible.

7. The Attention Strip

At the very top of the Assessment section — above the ranked candidate list — is the Attention Strip. It always shows every candidate carrying a code 1 or 2, regardless of where that candidate ranks by probability.

The strip exists because probability ranking alone is not safe. A diagnosis that is 12% likely but immediately life-threatening must not scroll off the bottom because five more-probable benign diagnoses rank above it. The strip keeps it anchored at the top of the reader's attention.

If the Attention Strip is empty, no high-attention candidates are currently present. This is worth noting but does not mean the situation is low-risk — it means the evidence gathered so far does not strongly implicate a severe diagnosis. Continue filling gaps.

8. Narrate

The Narrate button generates a plain-language paragraph summarizing the current state of this problem's record. Click it at any time — it reads the current record entries and assessment and produces a paragraph covering:

  • What the person has reported and what has been measured
  • The leading diagnostic possibilities and the evidence behind them
  • What remains unknown — specifically, which high-priority gaps haven't been filled
  • What the gaps mean: what information would most change the picture if obtained

The paragraph is editable. Click inside it to revise wording, add context, or remove anything that doesn't apply. Once you are satisfied, it can be copied into any other record system or printed as part of the visit summary.

Narrate is particularly useful at the end of a visit to produce a handoff note, or to share a plain-language summary with the person and their family. It is written to be understood without clinical training.

9. Saving Work

Everything saves automatically as you work. Every record entry, every status update, every probability history row is written to disk the moment you make it. There is no Save button and no risk of losing work by closing the browser tab.

If you close the browser and come back later, open http://localhost:8766 again (with the proxy still running or restarted) and your data will be exactly as you left it.

The data lives on this machine. If the machine is lost or replaced, you will need a Bundle (see Section 10) to restore it elsewhere.

10. Save Bundle and FedWiki Export

Save Bundle

A Bundle is a portable full backup of the entire database — all people, all problems, all record entries, all probability histories. Use it to:

  • Back up your work to an external drive or cloud storage
  • Move the record to another machine running the coupler proxy
  • Hand off a complete record to another care team member

Click Save Bundle in the top toolbar. A .json file downloads to your machine. To restore it on any machine running the proxy, click Load Bundle and select the file. The entire database is replaced with the bundle contents.

Load Bundle replaces the current database entirely. If the target machine has its own records, save a Bundle from that machine first before loading a new one.

FedWiki Export

FedWiki export produces a one-way clinical view formatted for import into the Shared Care Plan (SCP) or a Groove workspace. It generates a set of FedWiki-formatted pages — one per problem — containing the filled findings, the assessment candidates, and the Narrate paragraph.

This export is read-only from FedWiki's perspective. Changes made in FedWiki do not flow back to the coupler. Use it to share a clinical snapshot, not as a sync mechanism.

Click FedWiki Export in the toolbar. A .json file downloads. Import it into your FedWiki instance using the standard page import procedure.

11. Print View

Click Print in the top toolbar to open a print-optimized view of the current problem's full record. The print view includes:

  • All SOAP findings with their current status and record entries
  • The ranked assessment candidates with attention codes and evidence
  • The most recent Narrate paragraph if one has been generated
  • Probability history table for each candidate

The print view suppresses navigation chrome and renders in black-and-white-friendly contrast. Use your browser's built-in print dialog (Ctrl+P or Cmd+P) to print or save as PDF.

Printing to PDF is a lightweight way to share a visit summary with a specialist or to create a point-in-time record snapshot without using the Bundle format.

12. Activation Band and the PANAS Check-in

The coupler can adapt how much of the frame is shown by default, based on how activated — how ready and confident — the person currently feels about managing their health. This is grounded in Judith Hibbard's Patient Activation Measure (PAM) research. The tool uses the PANAS Positive Affect scale as a one-minute proxy rather than the licensed PAM instrument.

Taking the Check-in

Click Take PANAS below the person's name in the sidebar. A modal opens with ten words:

active · alert · attentive · determined · enthusiastic · excited · inspired · interested · proud · strong

For each word, tap the number (1–5) that best describes how much you felt that way during the past week. The scale runs from 1 (Very slightly or not at all) to 5 (Extremely). All ten words must be rated — the form shows your running count. When done, select who is recording (person, CHW, or family) and click Save activation score.

The check-in takes about one minute. It is a state measure — "past week" scores fluctuate — so it can be repeated at each visit. The trajectory over visits is stored and shown alongside the probability histories.

The Four Bands

BandScore rangePlain meaningView default
1 10 – 24 Learning the basics — still building knowledge and confidence Focused: urgent candidates only, top 3 absent findings
2 25 – 31 Building awareness — engaged but not yet fully confident Focused: same as band 1
3 32 – 38 Taking action — actively managing, growing in confidence Full frame visible
4 39 – 50 Staying the course — high confidence, proactive self-management Full frame visible
Score ranges are provisional thresholds drawn from Watson & Clark manual norms (past-week adult M≈31, SD≈7). They will be updated when Mahoney's PA→PAM cut-points are obtained. The crosswalk is a named table in the proxy code — changing it never affects stored raw scores.

Focused View (Bands 1–2)

When a band-1 or band-2 score is on record, the default view shows:

  • Assessment: only candidates with attention code 1 or 2 — the ones that need action regardless of how likely they are
  • Subjective and Objective: filled and partial findings always shown; only the top three absent findings per section displayed
  • Plan options: phrased as "Ask your nurse, doctor, or CHW about this" rather than steps the person takes independently

A yellow bar at the top of the problem view states the band and shows a Show full frame button. Click it at any time to see everything. Clicking again returns to the focused view. The band score does not change.

Full View (Bands 3–4)

The complete frame is shown: all candidates, all absent findings, all plan options phrased as things the person can do. There is no filter bar.

Optional: Negative Affect Scale (NA-10)

The check-in modal includes an optional second set of ten words measuring negative affect: afraid, ashamed, distressed, guilty, hostile, irritable, jittery, nervous, scared, upset. This takes another minute. If completed, the score is stored alongside the positive affect score and visible in the record. It is not used to change the view in this version — it is kept so it can inform care team decisions and future analysis. High negative affect alongside low activation often signals distress that warrants gentler pacing independent of the band.

Activation History

The band badge in the sidebar shows the current band and, on hover, the raw score and date. Below it, the most recent prior score is shown in small text. The full history is included in Save Bundle exports — it travels with the person's record.

If activation is rising visit over visit, the record may be doing what Weed intended: teaching whoever touches it. The trajectory is stored from the first check-in so the pattern can be seen over time.
